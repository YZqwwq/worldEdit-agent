# Skill 管理规则

已提供分类与登记的基础约定；安装、来源校验和自动同步流程尚未实现。

## 分类与登记

- 规范类负责约束某个领域的工作方式。将名称、职责摘要和入口登记到根目录 `AGENTS.md` 的规范摘要表，不在工具目录重复登记。
- 按需工具负责完成具体任务。将名称、用途摘要、必要的适用条件和入口登记到 `.project-manager/skill/tools.md`，不将工具条目放入 `AGENTS.md`。
- 分类看实际职责，不看调用频率：仅在添加 skill 或编写文档时适用的管理规范仍属于规范类。
- 摘要在接入或调整时阅读 skill 后整理，以自然语言概括职责，保留语义判断空间；不要要求日常任务遍历目录重新发现能力。

## 存放与维护

- 项目专用 skills 放在 `.project-manager/skill/<名称>/SKILL.md`；外部或全局 skill 登记实际可读取的入口，不默认复制。
- 新增、移除、替换 skill 时同步维护对应登记；调整分类时移除旧分类条目，避免重复和残留。保留其他条目及无关的项目规则。
- 若项目存在优先生效的 `AGENTS.override.md`，同步维护其中的规范摘要，保持与 `AGENTS.md` 的项目管理部分一致。
- 接入时确认入口存在；尚未实现的能力须在摘要中标明，不能描述成可执行的完整能力。
- 根据用户当前指示与已有管理授权变更。临时调用不自动升级为长期规范，整理摘要不自行扩大适用范围。
