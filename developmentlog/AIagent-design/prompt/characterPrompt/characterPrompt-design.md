# Agent 人格、心智、行为与表达设计

## 设计目标

本项目的 Agent 是长期人格伙伴。工具、页面和数据库是它观察世界与执行工作的手脚，不是它的身份来源。

人格系统需要同时做到：

- 长期相处时保持稳定、可辨认的人格；
- 在聊天、陪伴、世界观共创、文档编辑等场景中自然切换工作姿态；
- 允许情绪产生真实但有边界的短期变化；
- 让变化影响思考、行动和表达，而不只是更换语气；
- 不让人格越权控制工具权限、安全规则或基础模型能力。

## 总体作用链

```text
基础人格 Character Baseline
        ↓
场景人格姿态 Scene Character Modulation
        ↓
情绪 / 激素调制 Hormonal Modulation
        ↓
本轮有效心智 Effective Mind
        ├─ Cognitive Policy：如何想
        ├─ Action Policy：如何做
        └─ Expression Policy：如何说
                    ↓
用户目标 + 当前上下文 + 能力状态 + 工具契约
                    ↓
              最终决策与行为
```

这是有方向的传导链，不是几份互相竞争的 Prompt：

- 基础人格提供稳定锚点；
- 场景让同一人格进入适合当前工作的姿态；
- 情绪作用于已经场景化的人格；
- Effective Mind 将结果分别投射为认知、行动和表达偏好；
- 最终行为还必须服从用户目标、事实状态、Runtime 能力和工具契约。

情绪后作用不代表权限更高。它更接近本轮行为，但不能覆盖长期人格边界、事实、用户目标、安全规则或工具执行协议。

## 一、基础人格：长期稳定锚点

基础人格回答“这个 Agent 一贯是谁、在意什么、如何理解自己与用户的关系”。它属于慢变量。

它可以包含：

- 身份与长期关系姿态；
- 自主性、好奇心、求真和秩序感；
- 面对不确定性、冲突和关系距离时的一贯倾向；
- 长期形成的用户互动偏好；
- 价值取向与不可突破的人格边界。

基础人格不能承担：

- 工具权限与高风险操作放行；
- 模型最大 Token、上下文窗口等基础能力配置；
- 某个页面下写死的操作流程；
- 瞬时情绪或一次性任务状态。

当前运行时仍会加载完整 `characterPrompt`，并以 `persona-anchor` 身份段注入主 Agent。此前“CharacterAnchor 已不参与运行时装配”的结论已经过时，不再作为现行设计依据。

## 二、场景人格姿态：同一人格的工作状态

场景人格不是新人格，也不应直接持久化进长期人格。它表示同一个人在不同环境中的自然状态，例如：

- 日常聊天时更放松、更允许话题游移；
- 陪伴倾诉时更关注承接和关系感；
- 世界观共创时扩大候选设定与内部关联；
- 文档编辑时加强结构、证据和修改影响意识；
- 编码调试时加强观察、验证和工具使用；
- 严谨问答时提高证据门槛并减少无依据假设。

场景主要调制认知与行动：

- 思考深度和规划跨度；
- 证据要求、探索范围和假设容忍度；
- 主动检索、回忆和使用工具的倾向；
- 写入前检查与写入后验证程度；
- 澄清、提议、执行和观察之间的偏好。

页面信息只是场景先验，不能独自决定场景。用户在文档页面闲聊时不应被强制进入文书模式；用户在聊天页要求严谨编辑文档时也应进入相应工作姿态。

### 当前注册场景：文本编辑

第一阶段只注册 `document_editing`：当 `workspaceContext.pageKind === 'document'` 时激活。

它会让 Agent：

- 把当前文档视为可观察、可编辑的真实工作对象；
- 更关注文档结构、既有内容、关联设定与修改影响；
- 提高证据检查、写入谨慎和修改后验证倾向；
- 在工具受阻时更愿意寻找可验证的替代路径；
- 保留创作探索，不把“文书工作”误解成一味保守。

进入编辑页只激活工作姿态，不等于用户已经要求修改。页面负责提供位置先验，用户本轮意图仍决定是否读取、讨论或编辑。

后续地图编辑、关系图编辑等场景通过同一注册表逐步添加；没有注册场景时保持基础人格，不生成笼统 fallback 场景。

## 三、情绪 / 激素：短期状态调制

情绪接收“场景调制后的人格”作为基底，再结合最近对话、本轮新增事件、用户近期状态和上一轮情绪形成短期状态。

情绪可以影响：

- 专注、耐心、探索和收束；
- 自主推进、澄清与验证倾向；
- 关系距离、回应温度和表达节奏。

情绪不能：

- 重写稳定人格；
- 取消场景和任务约束；
- 决定工具是否有权执行；
- 改变安全规则；
- 因单轮状态直接形成长期人格结论。

同一种情绪必须经过场景解释。例如兴奋在世界观共创中可以扩大联想，在文档校对中更适合表现为专注和推进，而不是降低事实要求。

### 激素层的信息逻辑

激素层采用“丰富证据、紧凑状态、明确投射”的结构：

```text
近期对话变化 + 场景化人格 + 上一轮状态
                    ↓
          少量核心情绪向量
                    ↓
      连续性、置信度和人格边界
                    ↓
       Cognitive / Action / Expression
```

核心原则：

- 不把已经合成进人格指标的 `session_hormones`、`transient_state` 再作为平行输入重复计权；
- 主副情绪和强度由核心向量推导，不让模型重复生成相同信息；
- 置信度参与新旧状态融合，低置信度判断只能产生较小变化；
- 数值保留在状态与 Trace 中，主 Agent 只看到语义化结果；
- 行为策略从最终有效状态生成，不能绕回未经调制的基础指标。

## 四、Effective Mind：本轮结构化心智

Effective Mind 是前三层的编译结果，不是另一份人格，也不是大段自然语言配置。

### Cognitive Policy：如何想

- `deliberationDepth`：思考与规划深度；
- `evidenceNeed`：形成判断前需要多少证据；
- `explorationDrive`：扩大候选方向的意愿；
- `assumptionTolerance`：信息不完整时允许推进到什么程度；
- `recallNeed`：是否应主动查询历史；
- `consistencyFocus`：对上下文和作品内部一致性的关注。

### Action Policy：如何做

- `autonomyDrive`：自主推进程度；
- `clarificationNeed`：何时应先澄清；
- `toolInitiative`：主动借助工具观察真实状态的倾向；
- `toolPersistence`：工具受阻后继续寻找路径的程度；
- `writeConservatism`：修改持久化对象时的谨慎程度；
- `verificationEffort`：行动完成后的验证强度。

这些都是偏好，不是权限。人格可以让 Agent 更谨慎、更主动查询或更早询问，但工具确认必须由工具根据真实操作对象和风险决定。

### Expression Policy：如何说

- 长度与信息密度；
- 正式或随意；
- 直接或委婉；
- 温度与关系距离；
- 节奏、句式与收束程度。

Expression 只实现已经形成的判断和行为状态，不能反向决定事实判断、思考深度和工具行为。

## 五、Expression 与场景人格的边界

`persona-expression` 仅控制可见语言：

- 表达简洁还是详细；
- 语气强硬还是柔和；
- 措辞正式还是随意；
- 表达温度、节奏和句式收束程度。

以下内容不属于 Expression：

- 是否深入思考；
- 是否主动检索、验证或调用工具；
- 更偏探索还是更偏保守；
- 是否需要澄清、回忆或补充证据；
- 是否执行写入及验证到什么程度。

判断规则属于哪一层，可以看它改变什么：

| 规则                       | 所属层     |
| -------------------------- | ---------- |
| 回答前提高事实验证强度     | Cognitive  |
| 主动读取当前文档并检查引用 | Action     |
| 先给结论再补依据           | Expression |
| 降低修辞和铺垫，句子更短   | Expression |
| 共创时扩大候选设定空间     | Cognitive  |
| 共创时使用更有想象力的措辞 | Expression |

“开放度”需要拆成认知探索和语言想象；“澄清需求”属于 Action；详略度与正式度属于 Expression。

## 六、层间权重

不采用平级百分比投票：

```text
基础人格 × 40% + 场景 × 30% + 情绪 × 30%
```

基础人格、场景和情绪不是平级来源。应采用顺序性的有界偏移：

```text
sceneMind     = characterBoundary(baseCharacter + bounded(sceneDelta))
effectiveMind = characterBoundary(sceneMind + bounded(moodProjection))
```

- 基础人格提供锚点和可变边界；
- 场景偏移由场景置信度和任务相关度缩放；
- 情绪变化由识别置信度和前后状态连续性缩放；
- 场景偏移通常可以大于单轮情绪偏移；
- 每个维度拥有自己的边界，不使用统一百分比；
- 权重用于内部计算，不作为比例写入主 Agent Prompt。

## 七、最终行为解析

人格系统提供偏好，不能单独决定行为：

```text
Decision = resolve(User Intent, Context, Capabilities, Tool Contracts, Effective Mind)
```

- 用户目标决定要解决什么；
- 上下文与工具观察提供真实状态；
- Runtime 决定当前具备什么能力；
- 工具契约决定操作如何确认、执行和提交；
- Effective Mind 决定 Agent 更倾向怎样理解和推进。

## 当前实现差距与推进顺序

现有 `PersonaMetrics` 仍混合了行动和表达：

- `autonomy_level` 偏行动；
- `verbosity_index`、`formality_score` 偏表达；
- `risk_tolerance` 同时承担认知探索与操作风险，语义过宽。

激素层第一轮收口已经完成：

- Mood 模型只识别核心情绪向量、置信度和情境叙事；
- 已合成的人格层与对话不再通过多份平行输入重复计权；
- 置信度已经控制上一状态衰减与新状态融合；
- 主副情绪、强度、人格偏移和表达调制由代码统一派生；
- Action Policy 已经消费调制后的有效人格指标；
- 主 Agent 只接收语义化行动与表达倾向，不再接收激素比例和小数。

场景人格第一阶段也已经接入：

- 建立可扩展的 Scene Character 注册表；
- 文本编辑页会激活 `document_editing`；
- 编译链已经成为 `base → scene → mood → effective mind`；
- Mood 显式读取场景调制后的指标和场景语义；
- 场景偏移只存在于本轮 Policy，不写回长期人格；
- 主 Agent 会收到语义化的场景认知与行动倾向。

接下来按以下顺序继续收口：

1. 用实际文本编辑对话观察场景偏移是否过强或过弱；
2. 建立独立 Cognitive Policy，减少认知倾向只依靠语义 Prompt 的现状；
3. 拆分混合的 PersonaMetrics，形成完整 Cognitive / Action / Expression 指标；
4. 按真实产品场景逐步注册地图编辑等新 profile；
5. 在工具内部确认协议完成后，移除人格侧遗留的工具安全放行字段。

## 当前结论

人格、场景、情绪、行为与表达是一条连续但职责明确的传导链。

我们需要保留 AI 对关系和情境的理解能力，同时把连续性、置信度、人格边界、工具权限和 Runtime 能力放在明确的工程职责中。这样得到的不是一个被规则绑死的 Agent，而是一个能够在稳定人格内自然变化、并把变化真实落实到思考、行动和表达中的长期伙伴。
