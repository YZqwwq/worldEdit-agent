# Agent 核心待办

## 当前基线

- 每条用户消息形成独立 Turn，主 Agent 串行消费消息。
- Reasoning、工具观察、Final Composition 和提交边界已经分离。
- 工具拥有注册表、调用预算、结构化结果、EffectReceipt 和单轮执行账本。
- Context 已按来源分段并生成 Manifest；长期记忆默认按需 Recall。
- Scene/WorldFocus 独立执行链已移除，页面只提供工作环境，对象事实由 Agent 按需查询。
- 当前架构足够继续扩展能力，不需要整体重构。

## P0：真实模型端到端验收

使用当前正式模型完成连续对话与多工具场景，验证：

- 工具前后的自然语言思考保持连续，工具结果会改变后续判断。
- 已确认的对象、文档和 revision 会被后续步骤沿用，不重复搜索。
- Final 回复不会泄漏内部过程，也不会把主体态度整理成无人格报告。
- 空响应、工具失败、模型超时和中断都能形成清楚的用户结果。
- 普通对话首轮不产生无消费者的额外模型调用。

详细的人格表现与世界认知场景分别记录在对应专题，本文件只负责整体验收。

## P1：Context 与工具治理

### Context 用量

- 统计每段 Context 的来源、字符数、估算 Token 和实际 Provider Token。
- 区分稳定人格、近期对话、页面、记忆、工具协议、工具观察和 Final Composition 成本。
- 先提供 Turn 级报告，再根据真实占用决定去重、压缩或省略顺序。
- 超预算时必须保留身份、当前请求、任务状态和关键证据，并明确哪些内容被省略。

用户影响：长对话和多工具任务不会在不知情的情况下持续变慢或丢失关键上下文。

### 工具目录与 Quick Access

- 工具增加后继续保持“能力摘要 → 按需激活具体工具”的两级结构。
- Quick Access 只统计成功且被模型实际消费的调用，并按世界、页面和时间衰减。
- 保持少量推荐槽，并能说明推荐原因；无真实错配前不扩展复杂推荐算法。

用户影响：Agent 能获得更多能力，但默认 Prompt 不随工具数量线性膨胀。

### Recall 数据库验收

- 覆盖待归档原始消息、阶段记忆和长期记忆三种来源。
- 验证自然指代、最近轮排除、未完成 Turn 隔离和修订后的旧记忆失效。

## P1：运行可靠性余项

这些问题有价值，但当前不阻塞人格与应用能力优化：

- 中断请求绑定目标 `eventId + turnId`，避免迟到请求作用于下一轮。
- 提交后统计、归档和通知进入最小幂等 Outbox。
- 为聊天、Persona、Mood、Memory 和可逆工具副作用建立正式撤回边界。
- 用图片、地图等真实生产者验收多 Effect；没有生产者的旧分支不继续扩张。
- 将现有强杀恢复测试保持在 Electron 原生验收中。

用户影响：主要改善极端时序、崩溃和撤回场景，不应以明显增加普通 Turn 延迟为代价。

## P1：长期状态治理

长期记忆、关系、承诺和 Self Experience 的候选提取统一由 `thinking.md` 中的 Post-Turn Observer 推进。本文件只要求：

- 候选不能绕过各自权威服务直接写入正式状态。
- 每次长期变化都能追溯到 Turn、证据和 revision。
- 后台治理失败不能影响已经完成的用户回复。

## 暂不推进

- 为当前单一模型提前建设复杂 Provider 抽象。
- 在没有成本数据前设置 Turn 总 Token、费用或时长硬限制。
- 为没有真实需求的工具增加统一预览、批量协议或新的安全层。
- Turn Version 增量压缩；先观察真实快照规模和重复率。
