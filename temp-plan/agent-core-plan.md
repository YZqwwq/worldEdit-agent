# Agent 核心待办

## 当前基线

- 每条用户消息对应独立 Turn，用户控制采用中断而不是暂停/继续。
- Graph 只生成工作区草稿，正式状态由统一 Committer 发布。
- 工具调用具有单轮账本、结构化结果、调用次数限制和 EffectReceipt 基础。
- Context 已有最终 Manifest；长期记忆默认按需回忆，不直接全量注入。
- 独立 Scene/WorldFocus 执行链已移除；场景与对象由主 Agent 直接理解，实体工具结果通过 Tool Evidence 传递紧凑引用。

## P0：下一设备真实场景验证

本轮只完成代码收口与自动测试，下一次开发必须在可用的真实模型环境验证：

- 普通闲聊不再产生 Scene/WorldFocus 快速模型调用，首轮延迟应相应下降。
- 询问人物、国家、地区和势力时，主 Agent 能根据任务是否依赖既有事实，自行决定搜索或阅读。
- 搜索或读取成功后，下一次模型循环可见实体的 `id/type/name/worldId`，不重复搜索已确认对象。
- 只做命名、自由创作或假设讨论时，不因“缓存缺失”被强制调用工具。
- 工具失败或同名歧义时不伪造实体 ID；工具命中不会自动污染长期认知或人物印象。
- 需要沉淀认知时，仍由 Agent 在获得足够证据后显式调用保存工具。

用户影响：减少每轮预判带来的等待和误拦截，让 Agent 像正常对话者一样根据任务需要查资料。

维护影响：对象扩展不再要求修改 Scene 分类、Focus Slot 和派生 Prompt；只要工具返回标准实体字段，引用即可进入现有证据协议。

## 运行链路审计（2026-08-21）

当前真实主链路为：消息与页面快照 → 任务生命周期判断 → 瞬时感知 → Context 装配 → 主模型与工具循环 → Memory 草稿 → Final 与 Workspace 统一提交。

## P0：运行与恢复闭环

### 正式撤回

当前撤回尚不能保证聊天、Persona、Mood、Memory、任务状态和外部副作用一起恢复。

目标：以提交清单和可逆 Effect 为边界实现正式撤回；不把“清理未提交草稿”伪装成撤回。

验收：撤回后重新启动应用，用户可见消息和 Agent 后续判断都回到同一提交点；不可逆动作必须明确保留并提示。

### 中断目标校验

中断请求必须绑定当前 `eventId + turnId`。重复、过期或属于上一轮的请求不能终止新 Turn。

验收：连续快速发送消息和重复点击中断时，每个请求只作用于目标 Turn。

### 提交后动作

工具统计、归档和后续调度需要最小 Outbox。正式提交成功后即使进程退出，动作也能幂等补做。

验收：在提交前后强杀进程，不会出现“数据已完成但通知、归档或统计永久缺失”。

### 崩溃恢复

- 闭合工具执行前、业务副作用完成后、Receipt 写入前等恢复窗口。
- `ready_to_commit` 只重试提交，不重新运行模型或工具。
- 普通 checkpoint 遇到未知副作用时保持 fail-closed。
- 在 Electron ABI 环境执行 SQLite 事务与强杀测试。
- 将恢复测试纳入默认核心验收入口。

验收：恢复不会重复写入、伪造完成结果或丢失已确认副作用。

### Effect 系统收口

让新的图片、地图或外部操作工具实际接入多 Effect 协议，验证 `effectKey`、恢复查询和用户提示；确认无生产者的旧 Effect 分支应删除。

## P1：工具与 Context 治理

### 快速判断成本

普通 Turn 的快速判断继续按真实延迟和职责收益审计；只有产生独立且被后续消费结果的判断才保留单独模型调用。

用户影响：避免无效感知调用持续放大普通消息的首轮响应延迟。

验收：每个保留的快速判断都有独立产物和明确消费者，移除后不会只是减少重复结论。

### Quick Access

- 只统计成功且被模型实际消费的调用。
- 引入时间衰减、成功率和完成贡献。
- 按世界、页面、任务和会话隔离。
- 保持最多三个槽，并提供可观测的入选原因。

验收：场景切换后不会继续推荐无关工具，失败或陈旧调用不会长期占位。

### 工具目录

Agent 先看到能力包摘要，再按需加载工具集协议与具体工具；补齐用途、入口、适用边界和内部任务协议。

验收：工具数量增长时，默认 Prompt 规模基本稳定，工具发现仍能命中正确能力。

### 世界认知与工具证据边界

- 让实体读取、搜索和解析工具通过显式合同声明已确认的对象引用；通用递归提取只作为兜底，不能把搜索候选或输入回显当作已确认对象。
- 保存认知节点父级时检查完整祖先链，拒绝把维度移动到自身后代下形成循环。
- 认知空间 revision 使用数据库原子递增，保证并发保存不同卡片时仍是可靠的变更标识。
- 文档搜索回退普通检索时保留认知服务异常的内部 Trace，不向用户暴露内部故障，也不静默失去检修线索。

验收：模糊候选不会污染本 Turn 对象引用；认知树不可能成环；并发写入不会丢失空间 revision；认知缓存故障可诊断且不阻断普通搜索。

### Context 预算

- 统计每段来源、字符数和估算 Token。
- 对页面信息、人格、工具说明和 Recall 结果按来源去重。
- 设置总量保护线和可恢复省略，身份、当前请求、任务状态和关键证据不可静默丢失。

验收：超预算时模型知道省略了什么，并能通过稳定引用继续读取。

### Recall 集成验收

补齐待归档原始消息、阶段记忆和长期记忆三来源的真实数据库用例；验证自然指代、最近轮排除和未完成 Turn 隔离。

## P2：长期记忆

- 将阶段摘要保留为压缩历史，不再承担全部长期记忆。
- 静默提取独立重要事件，保存主体、时间、证据、置信度、来源、修订和失效关系。
- 区分事实、Agent 评价、用户偏好与短时情绪。
- 将临时用户状态与长期用户印象分离。
- 长期事件仍通过核心回忆工具按需进入 Context。

验收：事实被纠正或质疑时，Agent 能回忆证据并修订判断，而不是让旧摘要永久覆盖新事实。

## 暂缓

- 高风险工具的应用内确认协议，在首个真实不可恢复操作出现时实现。
- Turn Version 体积治理，先记录快照大小与重复率，再决定引用或增量存储。
