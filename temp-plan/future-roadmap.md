# 后续开发总路线图

## 文档定位

本文是当前阶段之后的统一执行入口，用于回答“下一步做什么、为什么先做、做到什么程度算完成”。详细协议仍保留在以下专题文档中：

- `agent-turn-interrupt.md`：用户主动中断、现场封存和 interrupted Turn 提交。
- `turn-version-design.md`：持久化版本、进程重启与崩溃恢复。
- `temp-context.md`：Context、Recall、瞬时感知、长期记忆与单轮执行生命周期。
- `temp-toolsystem.md`：工具注册表、工具目录、Quick Access、调用协议与错误恢复。
- `temp-plan-ducoment.md`：页面感知、世界文档工具、编辑同步与后续局部编辑。

更新专题方案时，应同步更新本文的阶段状态；本文不重复展开底层字段设计。

## 当前基线

以下能力已经形成可继续迭代的基础：

- 页面快照可随用户消息进入队列、Agent State 和 Context，能定位当前世界、实体及文档。
- Agent 可以跨页面读取世界文档，并执行创建、更新、重命名、移动和删除。
- 文档写入具有 `revision` 乐观锁和编辑器冲突保护。
- 工具完整结果可在同轮被模型消费，本轮 Ledger 能记录已执行动作与结果。
- 工具注册表具备启动校验，业务错误采用结构化结果返回。
- `completionSemantics`、`task_context` 激活和任意正整数 `turnCallLimit` 已落地。
- 图循环具备受限收尾机制，不以提高递归上限掩盖重复调用问题。

当前重点已经从“接通能力”转为“真实验收、治理和可持续扩展”。

### 2026-08-13 运行控制方向调整

产品不再提供“暂停并继续同一个 Turn”。用户在 Agent 运行时采取的是对话打断：当前 Turn 结束，已经展示的回复、完成的工具信息和执行现场被保存，下一轮 Agent 基于这些事实承接用户的新消息。

更改原因：

- 对具有人格连续性的 Agent，用户插话更接近终止当前表达并开始新一轮交流，而不是冻结内部 Graph。
- 暂停需要维护 continuation、安全边界、重复继续、队列所有权和持久化恢复等多套状态，产品收益不足以覆盖复杂度。
- Codex、Claude Code 等公开运行语义主要也是中断当前 Turn 后由会话历史承接；LangGraph 原生 interrupt 依赖 checkpoint 重新调用，并不保留 JavaScript 调用栈。
- 项目已经具备 AbortController、Turn Workspace、执行账本和统一提交入口，中断可以沿现有主链闭环。

- [x] 将消息队列收紧为未处理/正在处理；Interrupted Turn 提交成功后由队列把原 Event 完成为已消费。
- [x] 建立唯一 `commitInterruptedTurn`，原子保存部分回复、稳定 Workspace 和 Final interruption receipt。

- [x] 统一普通对话与后台人格阶段的中断边界，后台中断不再丢弃稳定 Workspace。

### 2026-08-12 架构收口计划

以下编号对应 `future-lack.md` 的统一系统审计问题，后续按编号逐项讨论和实施：

1. [x] **A1 中断与队列解耦：** 删除 `pausedEvent`；Turn 中断提交成功后队列将当前 Event 完成为已消费，不重新入队。
2. [ ] **A2 正式撤回边界：** 先决定降级或暂时禁用当前不完整撤回，再设计 Commit Manifest/Inverse Effects。
3. [ ] **A3 中断目标校验：** 中断请求精确绑定当前 `eventId + turnId`，重复或过期请求不能终止新的 Turn。
4. [ ] **A4 提交后恢复：** 为工具统计和 Memory Stage 归档增加最小 Post-Commit Outbox。
5. [ ] **A5 工具恢复收据：** 建立通用 `ChangeSet + EffectReceipt`，先以世界文档接入 `planned/receipt/unknown`，再开放普通 checkpoint 崩溃恢复。
6. [ ] **A8 恢复验收：** 将进程恢复测试纳入完整测试入口，修正 Node 20 native ABI 环境并完成 Electron 启动验收。
7. [ ] **A7 Effect 清理：** 删除确认无生产者的旧 Effect，维持 `commit_turn` 唯一正式提交入口。
8. [ ] **A6 快照治理：** 先记录 Version 体积和重复率，再决定大型工具结果引用方案。

收口标准：队列不再承担暂停控制；中断只产生一个原子的 interrupted Turn；已展示文本、稳定 Workspace 和完成工具结果不丢失；恢复不通过消息重新入队实现；Final 后状态不会被部分撤回；提交后动作可恢复；普通 checkpoint 不会盲目重放副作用。

## 实施原则

1. 先验收现有协议，再添加新的推理能力。
2. 工具成功不等于用户目标完成，必须区分动作结果与任务状态。
3. Agent 只承担目标判断和必要决策；标识解析、权限、重试和错误解释由工具系统承担。
4. 先建立版本与撤销边界，再开放更细粒度的自动写入。
5. 不保存模型逐字思维过程，只保留执行账本、证据和必要的短决策摘要。
6. 长期记忆继续静默生成，但默认按需回忆，不直接全量注入对话。

## 阶段 0：核心链路验收

**目标：** 确认已完成的协议在真实 Electron 对话和真实数据库中稳定工作。

### 工作项

- [ ] 补齐 Recall 三来源集成用例：待归档原始消息、阶段记忆、长期记忆。
- [ ] 实机验证工具完整结果在首次模型消费前不被摘要替换。
- [ ] 实机验证同轮 Ledger 能阻止无意义的重复搜索、重复读取和重复写入。
- [ ] 验证 `eventual` 工具只报告“已受理/运行中”，不会被表述为最终完成。
- [ ] 验证 `task_context` 工具在未激活任务时不可通过 Quick Access、手动挂载或常用槽绕过。
- [ ] 验证不同 `turnCallLimit` 的完整计数、拒绝结果及下一步建议。
- [ ] 为图循环保险收尾建立至少一条真实重复调用回归用例。

### 完成标准

- 核心自动化测试保持通过。
- 真实对话中不再出现因同轮重复调用导致的 `GRAPH_RECURSION_LIMIT`。
- 工具失败、次数耗尽和任务未激活时，Agent 都能解释现状并选择合法下一步。

## 阶段 1：Quick Access 治理

**目标：** 让常用工具槽反映当前场景下真正有用的能力，而不是永久累计调用次数。

### 工作项

- [ ] 只把成功且被模型实际消费的调用计入有效使用统计。
- [ ] 引入时间衰减，近期使用权重大于历史累计次数。
- [ ] 增加世界、页面、任务和会话作用域，避免跨场景错误推荐。
- [ ] 将失败率、重复拒绝率和完成贡献纳入排序。
- [ ] `task_context` 工具只在对应任务激活时参与候选。
- [ ] 保持最多 3 个快捷槽，并提供入选原因和统计观测信息。
- [ ] 为场景切换、时间衰减、失败调用和任务隔离建立测试。

### 完成标准

- 重启或切换页面后，Quick Access 不会错误保留无关工具。
- 高频失败工具不会因调用次数高而占据快捷槽。
- Quick Access 只改变工具发现效率，不改变权限和激活语义。

## 阶段 2：工具目录与 Context 预算治理

**目标：** 在工具数量和上下文来源继续增长前，控制可见内容的规模与重复度。

### 工作项

- [ ] 优化工具目录检索，使 Agent 先看到能力包摘要，再按需挂载具体工具。
- [ ] 为工具集补齐用途、入口、内部任务协议和适用边界。
- [ ] 利用最终 Context Manifest 统计各段字符数、估算 token、来源和保留策略。
- [ ] 对重复页面信息、人格信息、工具说明和 Recall 结果做来源级去重。
- [ ] 设置总量保护线和分段预算，但保留身份、当前用户消息、任务状态及关键证据。
- [ ] Scene 置信度较低时保留轻量历史世界焦点，不直接覆盖为“无焦点”。
- [ ] 建立工具发现命中率、挂载数、上下文规模和重复率观测指标。

### 完成标准

- 工具库扩张不会使所有工具定义常驻 Prompt。
- Context 裁剪有可解释清单，不会静默删除当前任务的必要证据。
- 页面感知、人格表达和按需回忆在预算治理后保持行为一致。

## 阶段 3：文档版本、Diff 与撤销

**目标：** 为 Agent 写文档建立可审计、可比较、可恢复的安全边界。

### 工作项

- [x] 先以世界文档验证统一副作用记录层：每次写动作生成持久化 EffectReceipt，同一轮多动作由 ChangeSet 聚合。
  - 2026-08-14：正式聚合已接通，并通过通用 effectKey、subject type 和引用字段验证未来图片、地图等资源无需修改 ChangeSet 模型。
- [ ] 设计文档版本记录，保存文档、revision、操作者、时间、变更摘要和前后版本引用。
- [ ] 为 Agent 写入生成结构化 diff 和人类可读变更说明。
- [ ] 支持单次变更撤销，并校验撤销目标 revision，避免覆盖后续人工编辑。
- [ ] 支持批量操作的变更集，使多文档修改能够整体审阅和撤销。
- [ ] 在编辑器中展示冲突、版本差异和恢复结果。
- [ ] 建立并发编辑、跨文档批量修改、撤销后再编辑的回归测试。

这里不为文档另建一套 Turn 记录协议：文档版本是业务历史，EffectReceipt 是跨资源统一的执行事实，ChangeSet 是任务级聚合。图片、地图和实体编辑后续按需接入相同协议；不要求本阶段一次迁移所有副作用工具，也不建设全工具虚拟文件系统。

### 完成标准

- 每次 Agent 写入都能定位来源、查看差异并恢复。
- 撤销不会绕过 revision 检查，也不会覆盖更新版本。
- 版本能力稳定后，才进入 TipTap 局部编辑。

## 阶段 4：TipTap 局部编辑与编辑上下文

**目标：** 从整篇文本替换升级为结构化、低冲突的局部操作。

### 工作项

- [ ] 定义 TipTap JSON 的标题、段落、列表等稳定节点寻址方式。
- [ ] 将当前选区、光标位置和选中文本作为短期页面上下文提供给工具。
- [ ] 增加节点读取、替换、插入、删除和移动能力。
- [ ] 局部操作仍通过 revision、diff、版本历史和撤销链路。
- [ ] 当节点已变化或定位失效时返回结构化冲突，而不是猜测写入位置。
- [ ] 验证局部编辑后目录、大纲、字数、自动保存与 Agent 页面感知同步。

### 完成标准

- Agent 可以只修改目标段落，未命中内容保持字节级或节点级不变。
- 人工编辑与 Agent 编辑冲突时有明确反馈和恢复路径。

## 阶段 5：长期记忆升级

**目标：** 将“滚动摘要”升级为独立的重要事件，同时维持按需回忆策略。

### 设计前置

- [ ] 明确重要事件的主体、时间、证据、置信度、来源、修订和失效语义。
- [ ] 区分事实事件、Agent 评价、用户偏好与短期情绪状态。
- [ ] 明确人格如何影响“值得记住”的选择，但不能改变事实证据。
- [ ] 设计旧事件被补充、纠正、质疑和取代时的演进方式。

### 实施工作

- [ ] 保留阶段摘要作为压缩历史，不再让它承担全部长期记忆职责。
- [ ] 静默提取独立重要事件，并保存可回溯证据。
- [ ] 将事件检索接入核心回忆工具，默认不直接注入首次 Context。
- [ ] 将 `userProfile` 拆分为临时状态与长期稳定印象。
- [ ] 当长期印象被用户质疑时，允许 Agent 主动回忆证据并重新判断。
- [ ] 建立事实纠正、同名实体、事件演进和人格评价隔离测试。

### 完成标准

- 短期窗口移出后，重要事实仍可被按需准确回忆。
- 被修正的旧事实不会继续以同等权重影响回答。
- Agent 的主观评价可演进，但与事实来源保持可区分。

## 暂缓事项

以下工作不进入当前连续实施链：

- 危险文档操作的应用内确认协议。待版本、diff 与撤销边界稳定后再处理。
- 为解决循环直接提高 LangGraph `recursionLimit`。递归上限只作为保险，不作为行为修复。
- 保存或展示模型逐字思维链。仅保留结构化执行账本、证据和必要决策摘要。
- 全量长期记忆直接注入 Context。长期记忆继续采用核心回忆工具按需读取。
- 在版本历史和撤销完成前开放大规模 TipTap 局部自动写入。

## 推荐执行顺序

1. 先按 A1、A3 完成中断与队列解耦，建立 `commitInterruptedTurn` 和端到端中断测试。
2. 验证下一轮可以承接中断前的部分回复、执行账本和已完成工具证据。
3. 再独立修订 Turn Version 恢复协议，按 A5 以世界文档完成最小 `ChangeSet + EffectReceipt`，并按 A8 完成真实崩溃恢复验收。
4. 按 A2、A4 收口正式撤回与提交后恢复。
5. 按 A7、A6 清理遗留职责并治理 Version 体积。
6. 完成阶段 0 的其他真实链路验收。
7. 实施阶段 1 的 Quick Access 治理。
8. 结合实际观测推进阶段 2，不凭估算过早压缩 Context。
9. 先完成阶段 3，再开展阶段 4；通用 ChangeSet/Receipt 与文档版本能力共用 revision/diff 基础，但职责保持分离。
10. 阶段 5 先完成产品语义讨论，再修改存储与 Recall。

任何阶段出现新的 P0 数据一致性、无限循环或权限绕过问题时，应暂停后续功能，先回到核心协议修复并补回归测试。
