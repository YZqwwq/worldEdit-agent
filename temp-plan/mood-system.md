# Agent Mood 架构与待办

## 当前架构

Mood 只评价当前用户消息、近期对话语境和用户交互事件。它不读取工具运行状态，也不决定工具权限。

快速模型输出离散事件评价：事件类型、正负影响、重要度、新奇度、未来倾向、责任归属、规范影响、关系影响、明确的掌控变化和置信度。

代码动力学维护三层状态：

- 短时情绪：喜悦、兴趣、惊讶、恐惧、愤怒、受挫、悲伤、厌恶、受伤。
- 慢速心境：积极基调、紧张、压力、无助、厌倦。
- 关系状态：信任、亲近、尊重、依恋、怨怼。

短时状态变化快，慢速状态逐轮积累，关系状态最慢。低置信度只能产生小幅更新，缺少新证据时状态逐渐回归角色基线。

编译顺序固定为：事件评价 → 核心状态演化 → 角色边界裁剪 → 标签、强度、叙述及表达投影统一派生。完整 `MoodAssessment` 只有一个构造入口，边界层不接触派生字段。

当前消息与近期历史分开提供；历史不包含当前消息。普通中性消息只使状态维持或回归基线，不会自动累积厌倦。

## 作用边界

Mood 可以影响：

- 表达详略、正式度、温度、关系距离、收束程度和想象开放度。
- 谨慎、澄清、证据、回忆和写入保守等软行动倾向。

Mood 不可以影响：

- 工具是否可见、可用或获准执行。
- 工具风险等级和确认协议。
- 稳定人格的自主性与风险容忍。
- 对事实证据的真实性判断。

主 Agent 只接收主副情绪、状态叙述和编译后的语义倾向，不读取底层数值。

## 当前待办

### P1：配置收口

`hardRules`、首选主情绪和 presence 当前没有运行消费者。选择其一：编译进人格边界，或者删除无效字段。

验收：每个配置项都能找到唯一消费者和对应测试。

### P1：降级可观测性

快速评价模型失败时继续使用中性评价，但 Trace 必须区分“真实中性”和“模型降级”，保存精简错误原因。

### P2：评价输入压缩

快速模型不再读取完整内部状态向量，只保留理解关系连续性所需的语义摘要，避免旧情绪反向诱导当前事件评价。

## 测试要求

- 边界裁剪后派生字段一致。
- 普通下一轮仍保留慢速状态影响。
- 低置信度不造成情绪跳变。
- 当前消息不会同时作为新事件和历史事件重复输入。
- 普通中性对话不会自然累积厌倦。
- 同一用户事件在工具循环中只评价一次。
- Mood 不改变工具权限、自主性、风险容忍和工具持续性。
- 表达正式度不改变 Recall 等行动策略；Expression Profile 不包含认知或行动规则。
- 模型失败可诊断且不会破坏当前 Turn。
