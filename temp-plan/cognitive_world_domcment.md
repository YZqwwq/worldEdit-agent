# Agent 世界文档认知设计

## 当前进度（2026-08-21）

P0 持久化边界、P1 最小工具闭环、P2 文档发现接入，以及 P3 的人物阅读范围迁移已经完成：

- 已建立 `Agent + World` 唯一认知空间，以及维度/概念共用的统一节点表；
- Markdown 是卡片正文真源，来源文档 ID 与 revision 独立保存；
- 主 Agent 使用内部稳定身份 `main-agent`，工具不向模型暴露或允许切换 `agentId`；
- 已提供 `query_world_cognition` 与 `save_world_cognition`，并注册到现有世界文档能力包；
- 概念节点必须属于维度且至少引用一篇当前 revision 的来源文档；
- 认知更新使用 expected revision，过期认知或过期文档证据不会覆盖新状态；
- 任意入口导致文档 revision 变化或删除时，引用它的有效认知会在同一数据库事务中进入 `needs_review`；版本恢复、分支切换和合并不会绕过该边界；
- 文档搜索会按需查询当前主 Agent 的少量认知卡片：有效认知只提高相关文档的阅读优先级，待验证认知只给出警告，认知服务失败时仍正常完成普通搜索；
- 人物目录、全量阅读任务、分批阅读和人物印象新鲜度判断统一使用人物认知引用的文档；“全量”现在表示认知范围内全量，不再表示整个世界；
- 缺失、待验证、同名或间接名称命中的认知不会自动绑定人物，也不会回退到全世界读取；旧阅读任务绑定精简的认知 ID/revision，认知变化后会要求重建任务；
- 读取人物目录时只加载认知范围内文档正文，世界中其他文档仅使用路径所需的结构元数据，减少无关内容读取与 Context 暴露；
- 已验证自由维度、别名查询、Agent/世界隔离、双 revision 冲突和全库显式迁移。

下一步应先用真实人物文档验证认知建立、阅读和印象刷新的完整体验，再决定是否把自由概念候选接入 WorldFocus。当前 WorldFocus 的人物印象新鲜度已经使用认知范围，但瞬时焦点识别仍只识别应用实体；在出现明确场景收益前不继续扩张认知结构。

## 目标与定位

世界文档是世界事实的真源，但自由文档树不再强制绑定人物、国家、地域等应用实例。Agent 因此需要在阅读文档后，逐步形成一套属于自己的世界认知，用来回答：

- 用户提到的名称、简称或别称可能指什么；
- 一个概念应优先阅读哪些文档；
- Agent 曾经如何组织和理解这个世界；
- 文档发生变化后，哪些旧认识需要重新确认。

这套认知不是第二份世界设定数据库，也不替代搜索、树浏览和精确阅读。它是 Agent 维护的轻量导航与理解索引：帮助 Agent 更自然地再次认识同一对象，真正回答事实时仍以当前世界文档为准。

## 所有权边界

认知在语义上归属于 Agent，但必须按世界隔离。准确关系是“某个 Agent 对某个世界形成的认知空间”：

```text
Agent
└─ 对世界 A 的认知空间
   ├─ 人物
   │  ├─ 菲尔娜
   │  └─ 洛兰
   ├─ 国家
   │  └─ 银月帝国
   └─ 力量体系
      └─ 灵质魔法
```

- 世界保存事实和文档，认知空间保存 Agent 对事实的组织方式与阅读入口。
- `agentId` 表示形成认知的长期主体，不等同于可变化的 Persona 配置。人格调整不应清空认知。
- `worldId` 防止不同世界中的同名人物、国家和设定相互污染。
- 认知可以引用世界文档，但不归属于某篇文档、文档树节点或人物实例。
- 世界级搜索索引仍是公共的文档发现能力；认知是某个 Agent 使用搜索和阅读后形成的可修正结果。

如果当前产品只有一个主 Agent，第一版仍应保留稳定的 Agent 所有权概念，避免以后出现第二个 Agent 时迁移整套认知；无需因此提前建设多 Agent 管理系统。

## 自由维度与小卡片

人物、国家、组织、事件、力量体系等维度由 Agent 根据世界内容自行建立，不在代码中维护固定语义枚举。系统只认识两种结构角色：

- **维度节点**：说明一组概念如何被 Agent 归类，例如“人物”或“北境政治势力”。
- **概念节点**：一张具体认知卡片，例如“菲尔娜”或“银月帝国”。

维度节点和概念节点使用同一种持久化结构。节点通过稳定 ID 和可选父节点形成简单树，因此 Agent 可以新增、重命名、移动和继续细分维度，而不需要修改数据库 Schema。

维度本身也保存 Markdown。例如“人物”维度可以描述 Agent 当前认为哪些内容适合进入该维度，以及建立人物卡片时习惯关注哪些信息。这使维度不仅是一个分类字符串，也保留了 Agent 对分类方式的理解。

每个概念使用一张短小、独立的 Markdown 卡片：

```md
# 菲尔娜

- 名称：菲尔娜
- 别称：菲、银发剑士
- 主要文档：角色/菲尔娜
- 相关文档：银月骑士团、北境战争

菲尔娜是银月骑士团成员。需要了解其经历时，优先阅读主要文档。
```

名称、别称、主要文档等是给 Agent 的软约定，不变成固定数据库字段。不同维度可以形成适合自己的简洁表达，也允许随着 Agent 认识加深而调整。卡片应保存稳定的导航和认识摘要，不复制大段正文，不保存缺少证据的一次性猜测。

不采用“整个世界一份大型 Markdown”的方式。大文件会让局部更新、并发修改、失效判断和按需查询越来越困难，也会迫使每次调用携带大量无关上下文。

## 最小持久化模型

第一版只需要一个认知空间和一组统一节点。字段名称可在实现时遵循现有数据库规范，逻辑结构如下：

```ts
AgentWorldCognitionSpace {
  id
  agentId
  worldId
  revision
  updatedAt
}

AgentWorldCognitionNode {
  id
  spaceId
  parentId?        // 所属维度，允许继续嵌套
  nodeKind         // dimension | concept，只表示结构角色
  title            // Agent 自拟标题
  markdown         // 认知正文真源
  documentRefs[]   // documentId + 已验证 revision
  revision
  status           // available | needs_review
  createdAt
  updatedAt
}
```

`documentRefs` 必须作为运行元数据独立保存，不从 Markdown 反向解析。Markdown 是供 Agent 自由组织的认知正文；文档引用还承担来源追溯和失效检测，不能因为 Agent 改变排版或字段名称而失效。

数据库逐卡片保存 Markdown 正文即可，不必真的在磁盘上创建大量 `.md` 文件。将来如需导入导出，可以再把认知空间映射为 Markdown 目录，但不应让文件系统形式先约束运行时设计。

## 与现有能力的职责关系

### 文档工具

现有三个世界级发现入口保持不变：

1. 搜索引擎负责在未知对象时广泛召回候选；
2. 树状深入负责理解自由文档目录；
3. 精确阅读负责读取已知文档及章节。

认知命中只提供优先候选和历史阅读入口，不取代这些工具，也不限制 Agent 阅读世界中其他文档。文档 revision 不匹配、对象同名、证据冲突或 Agent 对结论产生怀疑时，应重新搜索和阅读。

### WorldFocus

当前 WorldFocus 负责判断“这一轮正在谈论哪个应用内世界实例”，依赖实体 mention index，并可读取人物印象。它不能识别只存在于自由文档、没有应用实例的概念。

认知系统负责“这个概念有哪些称呼，应从哪些文档重新认识”。两者定位不同：

- WorldFocus 是本轮瞬时焦点；
- 世界认知是跨轮次、按需读取的概念导航；
- CharacterImpression 是 Agent 对具体人物的主观印象；
- 文档是事实真源；
- 长期记忆保存用户与 Agent 的经历、关系和重要事件。

第一版不重构 WorldFocus。先让主 Agent 通过工具按需查询认知，闭合认知的创建、复用与修正；稳定后再评估是否把认知候选作为“自由概念焦点”来源接入 WorldFocus。这样可以避免在认知数据尚未形成时同时改造瞬时感知链路。

### 人物印象

人物印象不应把整套世界文档当作人物材料。认知稳定后，人物印象等上层能力可以利用认知卡片选择主要文档与相关文档，再进行事实阅读。认知卡片本身不能直接充当人物印象，也不能把主观印象反写成世界事实。

## 创建、更新与失效

Agent 只有在至少阅读过一份相关文档，并形成可复用的名称、称呼或文档入口映射后，才应保存认知。一次性联想、低置信度猜测和仅来自用户当前措辞的推断不应立即持久化。

建议生命周期：

1. 首次遇到未知概念时，使用搜索、树浏览和精确阅读确认候选；
2. 确认存在可复用认识后，创建维度或概念卡片并记录来源 revision；
3. 再次遇到相同名称或别称时，先查询认知，取得文档候选；
4. 来源 revision 仍有效且没有冲突时，可以直接按候选精确阅读；
5. 来源文档改变、删除或证据冲突时，将卡片标记为 `needs_review`；
6. Agent 重新阅读后修正卡片和引用，再恢复为 `available`。

失效不等于删除。旧认识可能仍有解释价值，也可能只需更换一个文档入口。系统不自动重写 Markdown；它只提供明确状态，让 Agent 在合适场景下重新判断。

同名对象不得静默合并。若证据不足，应保留多个候选或继续搜索，而不是为了得到唯一结果修改已有认知。

## Agent 工具方向

第一版增加两个认知工具即可：

- `query_world_cognition`：在当前 Agent 的当前世界认知空间中，按名称、别称、标题或正文查询维度和概念卡片；结果保持小而可追溯。
- `save_world_cognition`：创建或修正维度/概念节点，同时显式提交父节点、Markdown、来源文档 revision 和预期认知 revision。

查询工具不应把整套认知注入 System Prompt。主 Agent 在用户提到陌生概念、简称，或者需要确定阅读范围时按需调用。保存工具应支持基于 revision 的更新校验，防止旧工具结果覆盖较新的认知。

第一版可把“标记待验证”纳入保存工具的状态更新，不必为每个动作拆出更多工具。是否需要浏览完整认知树，应在真实使用中出现需求后再决定。

## 推进方案

### P0：确定持久化边界（已完成）

- 建立 `Agent + World` 唯一认知空间和统一认知节点；
- Markdown 作为卡片正文真源，来源文档引用作为独立元数据；
- 支持自由维度、父子节点、认知 revision 和待验证状态；
- 不引入固定概念类型、固定字段 Schema、向量数据库或知识图谱。

验收：两个世界的同名概念互不污染；人格配置变化不影响认知；Agent 可以创建此前代码从未定义的新维度。

### P1：建立最小工具闭环（已完成）

- 实现按 Agent、世界和文本查询认知；
- 实现新建与修正认知，并进行 revision 校验；
- 保存来源文档 ID 与 revision；
- 为工具合同、跨世界隔离、父子维度和旧 revision 冲突增加测试。

验收：Agent 阅读文档后能保存一张卡片，后续通过简称重新找到卡片和文档入口；工具不会全量返回认知库。

### P2：接入文档发现与失效检查（已完成）

- 认知命中有效时，为搜索/阅读提供优先候选；
- revision 不一致、文档删除或候选冲突时回落到现有搜索与阅读；
- 将受影响卡片标记为待验证，不自动删除或自动篡改正文；
- 用真实文档操作验证移动、重命名、正文修改和删除的边界。

验收：认知能减少重复广搜，但错误或过期认知不会阻止 Agent 重新发现事实。

### P3：连接上层认知能力（人物阅读范围已完成）

- 已完成：人物印象通过认知选择阅读范围，不再读取整个世界；
- 待真实场景评估：把认知候选作为自由概念焦点接入 WorldFocus，而不是直接替换现有实体焦点；
- 根据实际 Context 用量和召回质量，决定是否需要认知树浏览、全文索引优化或更强检索。

验收：自由文档中的概念即使没有应用实例，也能被 Agent 持续认识；人物印象、瞬时焦点和世界事实仍保持清晰职责边界。

## 暂不处理

- 不固定人物、国家、地域等维度枚举；
- 不自动从每篇文档批量生成认知；
- 不把认知全量注入主 Prompt；
- 不把认知变成世界事实或自动创建应用实例；
- 不立即重构 WorldFocus；
- 不提前引入向量库、复杂知识图谱或独立 Markdown 文件仓库；
- 不在缺少真实使用数据时限制 Agent 可阅读的世界文档范围。

这些约束的目的不是限制未来能力，而是先建立一个简单、可修正、能自然扩展的最小闭环，为 Agent 自主形成世界认识保留空间。
