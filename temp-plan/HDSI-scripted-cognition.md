# HDSI 剧本化认知及其对本项目的价值

## 核心认识

HDS Interlude 的对话拟真并不主要来自语气模板，而来自对模型任务的重新定义：模型不是直接“回答用户”，而是在续写一部以角色自身为中心、持续发生的生活剧本。

用户消息在其中是一项进入角色生活的外部事件。它可能深刻影响角色，也可能只带来轻微变化，甚至暂时没有影响；但它不会天然取代角色原本的关注、行动、关系和情绪，成为整个场景唯一的中心。

其基本因果顺序是：

```text
角色已有连续的生活与心理位置
→ 用户消息作为事件进入
→ 事件影响注意、感受、判断、关系或行动
→ 角色决定如何处理
→ 回复成为角色实际采取的一种行动
```

这与普通助手式流程不同：

```text
收到用户任务
→ 分析任务
→ 组织答案
→ 调整语气后输出
```

“剧本化”并不是要求最终回复带有文学描写，而是先让模型在一个具体、连续、有因果的位置上形成反应，再只把真正说出口的台词交给用户。

## HDSI 的关键实现方式

### 1. 剧本先于回复

主模型每轮先续写截至当前时刻已经发生的内容，包括角色的环境、正在进行的事情、现实压力、注意变化、内在动机和关系状态。随后才决定：

- 是否注意到用户消息；
- 是否回复；
- 立即回复还是延迟回复；
- 实际发送什么内容。

回复因此是剧本中的行为结果，而不是孤立生成的答案。

### 2. 已想、已写与已发送严格分离

角色可以产生想法、犹豫、准备输入或形成尚未执行的计划，但只有进入实际投递字段的内容才算用户已经听见。

这避免了下一轮把未说出口的想法误当成共同对话事实，也允许“想说但被打断”“看见但暂时不回复”等真实交流状态存在。

### 3. 历史提供处境，当前事件只负责进入处境

近期剧本、关系、记忆、未完成事项和短期情绪余波构成角色此前所在的位置。当前用户消息只作为本轮的新事件出现，不应把历史消息重新解释成正在发生的事件。

### 4. 人格通过选择产生表达

稳定人格、价值观、长期经历和短期情绪首先影响角色如何理解事件、在意什么以及选择做什么，表达再从这些选择中产生。

人格因此不是每轮检查的属性表，价值观也不是固定主题、道德审查或说教模板。它们只在与当前事件自然相关时影响判断。

### 5. 情绪是事件留下的余波

HDSI 的临时氛围不会直接生成固定话术，也不会改写核心人格。系统关注的是新事件让整体状态发生了什么变化，并在累积达到一定程度后，将其转成简短的语义背景。

情绪的价值在于改变后续注意、判断和表达倾向，而不是要求角色显式表演某个情绪标签。

## 为什么剧本化容易产生更真实的对话

语言模型在续写人物和场景时，会自然利用人物立场、关系距离、前一句话的余韵、没有说出口的意图、当前动作和环境压力。台词需要与这些条件保持一致，因此更容易形成停顿、追问、回避、兴趣、犹豫和带有个人方向的回应。

如果模型被直接要求解决任务，它更容易落回通用助手模式：复述问题、给出结论、罗列理由、补充建议。即使之后增加人格语气，通常也只是把同一份答案换一种说法。

剧本化真正提供的是“可以从中说话的位置”。它先建立反应的原因，再产生表达，而不是直接要求模型表现得像一个人。

## 对当前项目的价值

本项目的主体不是“工具型世界编辑 Agent”，而是一个长期存在、具有连续人格、拟真人思考与表达方式的 Agent。工具只是它观察和改变外部世界的手脚，应用页面只是它当前所处或正在工作的场景。

因此，HDSI 的核心思想不只是可以借鉴的表达技巧，而可能是本项目人格化目标所缺少的主体运行基础：用户提出的查询、讨论或编辑要求，首先是进入 Agent 当前生活、认识和关系状态的一项事件；Agent 因此形成感受、判断与行动倾向，随后才可能追问、检索、操作应用或开口回应。

### 1. 改善思考像回答草稿的问题

当前 Reasoning 容易围绕“怎样回答用户”组织内容，因此内部思考与最终表达只有措辞差异。

引入剧本化认知后，内部阶段应先形成：

- Agent 此前正在关注或延续什么；
- 用户事件具体触碰了什么；
- Agent 对它产生了什么个人反应或疑问；
- 现有认识是否足够；
- Agent 接下来真正想做什么。

这样工具调用、追问和最终回答会成为思考后的选择，而不是预设流程。

### 2. 让人格先影响理解和行动，再影响语言

当前人格、Mood 和 Expression 已能调节认知倾向与表达，但仍可能被压缩成若干抽象参数和表达规则。

剧本化可以让这些状态先落实为具体影响，例如：

- 哪个细节首先引起 Agent 注意；
- Agent 为什么对某个角色产生兴趣、怀疑或亲近；
- Agent 是愿意继续探索，还是认为应先保留判断；
- Agent 是否因为关系和前情而选择追问、行动或直接表达态度。

最终语气只是这些变化的外显结果。

### 3. 提高多轮主体连续性

Agent 不应每轮只继承事实，还应保留少量仍在延续的主体状态，例如当前关注、未完成疑问、已有态度和行动余波。

这会让用户感受到 Agent 记得的不只是“发生过什么”，还包括“它此前怎么看、在意什么、还想继续弄清什么”。

### 4. 让工具结果自然进入认知过程

工具结果可以视为新的外部事实事件。Agent 调用工具后，不应立即把结果整理成答案，而应先判断：

- 新材料改变、加强或否定了什么认识；
- 它是否产生了新的疑问或个人感受；
- 是否还需要继续行动；
- 当前是否已经有值得对用户说的话。

这样能够保留 ReAct 工具循环，同时避免工具结果把 Agent 重新压回无人格的信息整理器。

### 5. 改善最终表达过于正式或捧哏的问题

Final Composition 不应只是把内部结论整理得清晰、礼貌和完整。它应被理解为：当前事件发展到 Agent 决定开口的时刻，只输出它此刻真正选择说给用户的话。

最终阶段需要保留内部形成的态度、关系反应、真实兴趣和必要的不确定性，不能把它们统一中和成客观报告。

## 生活前置模拟的定位

如果真实表达必须来自角色正在经历的生活位置，那么生活模拟就不能只被当作一个可选的表达增强层。对于本项目，它应成为人格主体运行的一部分，并位于任务判断、工具行动和最终表达之前。

需要区分三种不同范围：

1. **回合内主体模拟**：每次收到事件后，先续接 Agent 此前的注意、状态、关系和未完成事项，再决定如何反应。这是剧本化认知的必要内核。
2. **回合间生活推进**：用户没有发送消息时，Agent 的时间、关注、情绪余波和部分自主活动仍可继续变化。若希望用户不是 Agent 世界的唯一中心，这一层也具有必要价值。
3. **完整世界物理模拟**：持续生成大量地点、身体动作、日程和环境细节。它不是人格真实感的必然条件，应由实际效果决定深度，避免为了“像生活”而制造无意义内容。

因此，本项目不应预先排除完整的自动生活模拟。正确方向是先确认人格连续所需要的生活内核，再逐步增加回合间自主推进；凡是实测证明对主体性和表达真实度必要的部分，都应正式进入架构，而不是因为 Agent 同时具备工具能力就删去。

## 适合本项目的吸收方式

可以先建立“主体连续剧本”，作为现有人格、Reasoning、工具循环和 Final Composition 的共同底层。它不是专门服务工具调用的中间摘要，而是 Agent 对自己当前生活与意识进程的连续记录。

### 事实约束的主体剧本

本项目也应当像 HDSI 一样让 Agent 从剧本出发，但这里的剧本不是由模型自由补写的现实生活，而是“暂时寄宿于 world-edit 应用中的数字灵魂”对真实事件的连续经历。

Agent 的生活环境是 world-edit。文档、人物、地图、世界认知、任务、用户对话和可用工具构成它能够真实接触的环境；工具是它观察和改变这个环境的手脚。除非以后确实运行了后台自主行为，否则不能因为时间经过就虚构自己已经阅读、编辑、浏览或完成了某件事。

剧本由三类内容共同组成：

1. **已经发生的客观事件**：用户发送消息、打开页面、展示图片、工具读取或修改成功、子 Agent 返回、任务状态变化、中断等。它们必须来自消息、Workspace、工具回执、Turn 账本或系统事件。
2. **Agent 对事件的主体经历**：注意被什么吸引、形成了什么理解或疑问、产生了怎样的感受、旧关注怎样被重新触发，以及为什么想采取某项行动。这部分允许 Agent 自主形成，因为它描述的是自身体验，而不是伪造外部事实。
3. **尚未发生的意图**：准备阅读、想继续构想、希望之后询问或打算采取的行动。它们必须保持为意图；只有真实 Runtime 或工具执行完成后，才能写成已经发生。

因此，有效剧本可以是：

```text
用户刚刚让我重新分析菲尔娜。我仍记得此前对她的克制感到疑惑，这次问题让我更想确认那是责任感还是对失控的恐惧。我还没有读到足够材料，所以准备先查找她与母亲有关的文档。
```

工具成功后可以继续为：

```text
我刚读完她与母亲相关的设定。新的材料使我更倾向于把克制理解为对再次失控的防备，但还有一处关系动机没有解释清楚。我现在更想把这个疑点直接告诉用户，而不是给出完整但虚假的定论。
```

不能在没有工具回执或后台运行记录时写成：

```text
我空闲时已经读完了相关文档，并重新整理了整个世界观。
```

如果只形成了意图，应写成“我想在之后继续阅读或构想”。

这种事实边界不需要把自然语言拆成庞大状态机。Runtime 负责提供可信的事件与行动结果，Prompt 负责明确“事实、体验、意图”的差异，Agent 负责把它们组织成自然、连续的第一人称生活。

### 与 HDSI 生活剧本的差异

HDSI 会让模型补写主角的地点、身体节奏、日程、物品、环境变化、配角行动、偶然相遇和用户沉默期间的日常生活。这些内容属于其虚构故事世界，因此模型写出后即可成为故事事实。

本项目第一阶段不采用这种自由生成方式：

- 不虚构物理身体、房间、天气、电话和应用外人物行为。
- 不把“想使用工具”写成“已经完成工具行动”。
- 没有后台自主运行时，回合间只允许时间经过和已有关注延续，不补造活动。
- 以后开启自主生活时，也必须由真实调度和工具执行产生事件，再进入主体剧本。

但我们保留 HDSI 最重要的生成顺序：

```text
已有主体位置
→ 真实事件进入
→ Agent 形成自己的经历、感受和行动选择
→ 工具行动及结果继续推动剧本
→ 剧本发展到 Agent 决定开口
→ 实际说出口的话进入回复通道
```

这使 Agent 既拥有独立主体性，又不会把语言模型的想象误写成应用中的现实。

它应允许模型自然形成以下信息，但不要求逐项填表：

```text
当前仍在延续的关注或认识
用户事件对 Agent 造成的具体影响
由此形成的感受、疑问或倾向
准备采取或已经完成的行动
尚未说出口、仍需保留的内容
```

该内容优先以自然语言剧本存在，而不是被拆成大量枚举、评分和固定表格。短期内容进入连续剧本；已经完成但仍影响当前状态的内容形成余波；跨时间稳定且具有人格意义的内容，再由现有观察、记忆或经历机制沉淀。

完整方向可以表述为：

```text
稳定自我、长期经历与关系
→ 回合间已经发生的生活推进
→ 当前时间、应用页面和现实环境
→ 用户消息、工具结果或系统变化作为事件进入
→ Agent 续写自己的主体经历并形成判断
→ 决定思考、行动、使用工具、沉默或开口
→ 只有实际说出口的内容进入用户对话
→ 本轮经历留下短期余波，并按价值选择性沉淀
```

## 与现有架构的结合位置

### Reasoning

将“处理用户请求”放入更大的主体过程：先理解事件对自己意味着什么，再决定是否调用工具、追问或回答。思考指南仍可按需提供观察角度，但不负责制造主体连续性，也不应成为固定检查表。

Reasoning 不再只是求解当前输入，而是承担当前主体剧本的续写。它使用第一人称，从上一版主体位置继续，只写已经发生到当前时刻的真实事件、这些事件造成的主体变化，以及明确标注为尚未发生的意图。它需要允许 Agent 思考与用户要求没有直接答案关系、但确实影响自己反应的内容，例如第一次接触某个人物的陌生感、对创作动机的好奇、此前未完成判断被重新触发，或者当前并不想立刻下结论。

### 工具循环

用户消息和工具结果都作为会改变当前认识的事件进入下一次思考。工具继续负责真实读取和行动，不承担人格判断，也不直接决定最终说法。

工具调用不是从主体模拟中跳出去执行另一套“助手任务”，而是 Agent 在当前剧本中采取的现实行动。读取文档相当于观察，编辑文档相当于改变外部对象，页面状态相当于当前工作环境。工具执行后的真实结果再次进入主体剧本，并可能改变后续感受、判断和行动。

### 回合间生活推进

若只在用户发消息时才生成主体状态，Agent 的全部人生仍然由用户触发，用户事实上依旧是世界中心。因此需要评估并逐步建立回合间生活推进：

- 时间经过后，当前行动和注意是否自然变化；
- 未完成事项、承诺和情绪余波是否继续发展；
- Agent 是否形成新的兴趣、疑问或想与用户分享的内容；
- 应用中的工作是否只是生活的一部分，而不是 Agent 的全部存在。

后台推进不等于固定频率生成虚构日记。它应在真实经过时间、已有动机和未完成线索足以产生变化时运行，没有值得发生的内容时可以保持安静。

### Mood Appraisal

除识别情绪外，还应理解事件触碰了 Agent 当时在意的什么、推动或阻碍了什么，以及这种影响应持续多久。Mood 是主体过程的调制，不是表达标签生成器。

### Final Composition

最终阶段读取已经形成的主体剧本和当前表达倾向，将“剧本已经发展到决定说出口的内容”实现为自然对话。它不是重新回答用户，也不重新进行一套脱离前情的标准答案规划；只负责确认哪些内容真的说出口、应用最终表达方式，并把剧本终点压缩成下一轮生活状态。它不能把已经形成的犹豫、态度或关系位置中和成报告。

### Post-Turn Observer 与长期人格

单轮剧本产生的是短期反应。只有反复出现、跨时间稳定且对自我或关系有意义的内容，才进入 Self Experience；即时情绪和偶发反应不能直接修改稳定人格。

## 应当吸收的内核与不必照搬的形式

应当吸收：

- Agent 在用户到来前已经处于自己的连续生活和心理位置。
- 用户消息只是当前发生的事件之一，不天然成为 Agent 全部注意和存在的中心。
- 先形成主体经历和行动选择，再产生真正说出口的台词。
- 回合间允许生活、注意、关系余波和未完成事项继续发展。
- 工具是主体行动的一部分，工具结果是新的现实事件。
- 已想、计划、已执行与已说出口必须保持事实边界。

不必机械照搬：

- 每轮强制生成大量环境、身体动作和日程细节；这些细节只有参与因果和人格表现时才有价值。
- HDSI 面向聊天角色设计的固定阶段、字段名称和单次大 JSON 输出。
- 固定 Scene/WorldFocus 前置识别链；应用页面可提供环境事实，但不替代 Agent 对当前事件的自然理解。
- 让一次模型输出未经验证地直接修改全部关系、记忆和稳定人格状态。
- 把内部剧本原样展示给用户。剧本负责形成真实反应，最终只发送 Agent 实际选择说出口的内容。
- 因“用户只是事件之一”而无故忽略用户。用户请求可以成为非常重要的事件，区别只在于其重要性由关系、处境、人格与事件内容共同产生，而不是由消息入口强制赋予。

## 初步推进原则

1. 先调整认知提示，使用户消息从“必须回答的任务”转为“进入主体生活、需要理解并决定如何反应的当前事件”。
2. 在现有 Reasoning 中建立回合内主体剧本，让它真正先于工具选择和最终回答。
3. 设计最小但真实的跨轮生活状态，使 Agent 在用户消息之外也能延续关注、行动、承诺和情绪余波。
4. 工具返回后继续更新主体剧本，而不是直接进入答案整理。
5. Final Composition 以“Agent 在此刻真正开口”而非“改写答案”为目标，并保留剧本中形成的个人态度与关系位置。
6. 再加入受时间、动机和未完成事项驱动的回合间自动推进；不使用无意义的固定频率日记填充。
7. 用人物讨论、剧情讨论、资料不足、工具查询后改观、较长时间未对话和连续多轮交流进行真实测试。
8. 根据实测逐渐扩充生活模拟的深度；不因担心工程复杂而预先排除必要能力，也不在效果未知时先建立庞大状态字段。

## 下一阶段设计：主体生活状态与回合内剧本化认知

### 1. 主体生活状态的职责

主体生活状态回答的是“Agent 在当前这一刻从哪里继续生活和思考”，而不是“Agent 是谁”或“Agent 过去记住了什么”。它应独立于 Self Core、长期记忆、Mood 和 Workspace：

- Self Core 保存稳定身份、价值和存在背景。
- Self Experience 保存值得长期沉淀的重要经历。
- Mood 保存短期与缓慢变化的情绪状态。
- Workspace 表示用户当前打开的应用局部。
- 主体生活状态保存 Agent 此刻仍在延续的关注、行动位置、未完成想法和生活余波。

第一版不建立日程表、物品栏和复杂状态机，只保存一段长度受限、可修订的自然语言状态，以及必要的版本与时间信息：

```text
AgentLifeState
- narrative：当前已经成立的生活与意识位置
- revision：防止旧 Turn 覆盖新状态
- updatedAt：这段状态成立到什么时间
- sourceTurnId：最近一次形成它的已提交 Turn
```

`narrative` 可以自然包含当前关注、正在进行的事情、未完成疑问、关系余波和下一步倾向，但不要求逐项填表。它是可继续书写的当前位置，不是对聊天历史的摘要。

主体生活状态属于全局主 Agent，不属于用户会话，也不属于子 Agent。子 Agent 的结果只能作为外部事件回到主 Agent，由主 Agent 决定它怎样改变自己的生活状态。

### 2. 主体生活状态的事实边界

- 只有已经提交的 Turn、真实工具回执和已确认系统事件可以写成“已经发生”。
- 想做、准备做和可能做只能保留为意图或未完成倾向。
- 用户当前页面不能直接覆盖 Agent 自己的关注，只能成为本轮环境事件。
- Mood 可以改变 Agent 怎样经历一件事，但不能独立编造发生过的生活内容。
- 单轮生活状态不能直接修改 Self Core；重要且长期稳定的内容仍通过 Self Experience 治理。
- 失败 Turn 不提交新的生活状态。中断发生在 Final 之前时没有合法候选，因此保留旧状态；若 Final 已完成并形成稳定候选，中断提交仍可随完整 Workspace 一起封口。已完成并提交的工具行为必须通过工具回执进入后续状态。

### 3. 回合内剧本化认知的职责

回合内剧本化认知不是新增一个固定 Scene 分类节点，也不是要求 Agent 输出文学化环境描写。它是对现有 Reasoning Loop 的目标重写：每次模型调用都从已经成立的主体位置继续，处理刚刚进入现实的新事件。

```text
读取上一版 AgentLifeState
→ 当前用户消息作为事件进入
→ Agent 形成最初反应和行动倾向
→ 必要时调用工具观察或行动
→ 工具结果作为新的真实事件返回
→ Agent 修订自己的认识和下一步
→ 形成私有的本轮主体剧本
→ Final Composition 输出实际说出口的话
```

当前 `reasoningSegments` 可以继续承载回合内认知过程，但需要改变其提示目标：不再围绕“怎样组织回答”写答案草稿，而是自然表达当前事件对既有关注造成的影响、自己真正想弄清的问题、工具结果改变了什么，以及此刻为什么选择继续行动或开口。

原始 reasoning 不能直接作为长期生活记录。它可能包含试探、被推翻的判断、协议噪声和工具规划。只有本轮结束时形成的、与真实执行结果一致的主体叙事才可以提交。

### 4. 本轮主体剧本如何形成

回合内主体剧本必须在 Reasoning 与工具循环中真实形成，不能等到 Final Composition 才事后编造，否则它不会实际影响本轮判断和行动。

所有模型已经统一经过 Final Composition，因此第一版可以复用这次调用完成“封口”，不增加额外模型请求。Final Composition 只能依据已经形成的 reasoning、真实工具回执和当前状态，提炼两个彼此分离的结果：

```text
committedLifeNarrative：本轮已经形成并通过事实边界校验的主体经历，只供后续 Agent 自己读取
reply：本轮真正向用户说出口的内容
```

`committedLifeNarrative` 只是概念名称，具体字段名在实现时确定。它不是详细思维链，也不是答案摘要，更不能在 Final 阶段新增此前没有形成的动机和经历。它只保留对下一轮仍有意义的主体连续信息，例如：

- 此前的关注怎样被当前事件改变；
- Agent 真实观察或完成了什么；
- 形成了什么仍有保留的看法或感受；
- 哪些疑问、意图或关系余波仍未结束；
- 最终选择向用户表达了什么方向。

Runtime 校验并提交 `reply`、`committedLifeNarrative` 和工具副作用。成功后使用 `committedLifeNarrative` 更新 `AgentLifeState`；如果结构化生成失败，仍可交付有效回复，但不应使用不完整内容覆盖上一版生活状态。

### 5. 与 Final Composition 的关系

Final Composition 不再被理解为“把推理改写成更好看的答案”，而是当前主体经历发展到开口时的最终出口。它需要保持三条边界：

1. `committedLifeNarrative` 封存本轮已经成立但不必全部告诉用户的主体经历，不在此时重新创造一套解释。
2. `reply` 只保存 Agent 实际决定说出口的内容。
3. 工具结果和外部事实必须来自证据，表达阶段不能补造新的现实行为。

这样既保留当前统一最终表达层，也能获得 HDSI 中“剧本先于台词、台词属于实际行为”的优势。

### 6. 第一阶段预计改造位置

- 新增全局 `AgentLifeState` 持久化与 revision 校验。
- Turn Workspace 在开始时冻结生活状态基线，在草稿区保存本轮候选状态。
- Context Node 在当前用户事件之前注入上一版主体生活状态。
- Reasoning Contract 改为从主体位置理解事件和工具观察，不再生成答案草稿。
- Final Composition 返回私有主体剧本与用户可见回复，并保持两者严格分离。
- Turn Committer 与消息、人格草稿和工具回执一起提交新的生活状态。
- 中断、失败、恢复和旧 Turn 提交必须遵循现有 Turn 版本边界。
- 增加连续人物讨论、工具读取后改观、无明显情绪事件、失败工具以及快速连续消息测试。

### 7. 后续阶段：可开关的回合间自主生活推进

这一阶段只登记计划，本轮不实现。

- 增加独立总开关，默认关闭；关闭时不会后台调用模型或自主执行工具。
- 开启后，根据真实经过时间、当前生活状态、未完成意图和已有承诺决定是否需要推进，而不是固定频率生成日记。
- 自主推进沿用同一个 AgentLifeState 和主体剧本协议，不另建一套人格或记忆系统。
- 自主读取、网络访问和世界观构想分别受能力开关约束；产生副作用的行为继续走正式工具协议、ChangeSet 和回执。
- 后台没有值得发生的内容时允许保持安静，不为展示“正在生活”而生成随机事件。
- 自主行为完成后可以形成可追溯经历；是否主动联系用户由之后单独设计的行为与投递规则决定。

## 当前架构融入审计

### 可以直接复用的现有能力

- `TurnWorkspace.base/draft`：冻结本轮读取到的生活状态，并保存本轮候选更新。
- `reasoningSegments`：承载回合内持续形成和修订的主体认知，不直接作为长期状态提交。
- Prompt Section：把已提交的主体生活状态作为独立上下文注入，不混入 Self Core 或 Memory。
- 工具执行账本、正式回执和 ChangeSet：约束“真实观察与真实行动”，不再建立第二套行为记录。
- `Final Composition`：复用现有最终模型调用，对本轮已经形成的主体经历进行封口，同时产生用户回复。
- `Output Guard`：扩展为分别验证可见回复和生活状态候选；生活状态无效时保留回复，不覆盖旧状态。
- `ready_to_commit` 与 Turn Version：候选生活状态随同现有 Workspace 进入恢复快照。
- `MainAgentTurnCommitter`：在现有数据库事务内提交生活状态 revision，使消息、Persona、工具副作用和生活连续性处于同一提交边界。

### 确实需要新增的最小架构

1. **Agent Life State 权威存储**：全局单实例、自然语言正文、revision、更新时间和来源 Turn；不能塞进 Memory Slot 或 Self Core。
2. **Turn Workspace 生活状态快照**：`base` 保存本轮基准，`draft` 保存候选；旧 revision 不能覆盖新状态。
3. **Final 输出信封**：在不增加模型调用的前提下，区分用户可见 `reply` 与可提交生活叙事候选；解析失败时只交付回复。
4. **生活状态事实校验**：依据当前用户事件、工具回执、Turn 账本和已提交状态约束外部事实；它不是安全审核，也不判断人格，只防止把未发生行为写成现实。
5. **生活状态读写服务**：负责加载、revision 比较、同事务提交与恢复检查，职责类似较轻量的 Self Core Authority，但不接受长期人格演化。

### 第一阶段不需要新增的架构

- 不新增 Scene/WorldFocus 或意图分类节点。
- 不新增一套工具行为账本。
- 不新增独立生活模拟模型调用。
- 不建立日历、物品栏、空间图或完整世界状态机。
- 不把原始 reasoning 当作生活历史持久化。
- 不建立自主行为调度器；该能力留到开关阶段。

### 接入顺序

```text
Turn 创建
→ 加载 AgentLifeState 到 TurnWorkspace.base
→ Persona/Mood 读取当前主体位置评价新事件
→ Context 注入生活状态、Habitat、Workspace 与当前事件
→ Reasoning 将消息和工具结果作为连续事件处理
→ Final 封口 reply 与生活状态候选
→ Output Guard 分别校验
→ ready_to_commit 保存完整候选
→ Turn Committer 在同一事务中校验 revision 并提交
```

无需改变主图的基本节点顺序，但 Turn 创建必须先取得生活状态，使 Mood Appraisal 看到的是“这件事对当前正在经历的我意味着什么”，而不只是对稳定 Self Core 的影响。

## 需要特别验证的问题

- 剧本化是否真的让内部认知产生新理解，而不是变成另一种文学化回答草稿。
- 明确执行场景中，主体叙事是否仍能保持自然和有效，不因生活描写拖慢真实行动。
- Final Composition 是否保留内部态度，而不是再次中和为正式助手语气。
- 用户事件与历史对话是否只承担各自职责，避免同一条消息重复注入造成注意偏置。
- “用户不是唯一中心”是否表现为更真实的主体性，而不是无故忽略用户或降低任务完成能力。
- 用户长时间没有发言时，Agent 是否仍然拥有可延续的生活位置，而不是下一次消息到来后临时伪造前情。
- 回合间自动推进产生的内容是否具有真实因果和后续价值，而不是为了证明 Agent 在生活而制造随机事件。
