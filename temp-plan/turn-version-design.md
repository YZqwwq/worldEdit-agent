# Turn Version：单轮对话版本化缓存方案

## 目标

为主 Agent 建立统一的暂停、继续和崩溃恢复能力。

系统不分别为普通对话、工具、子 Agent 和记忆设计独立恢复流程，而是把一次对话视为一个持续存在的 Turn 缓存区。缓存区在稳定阶段生成不可变版本，只有整轮完成后才正式发布结果。

核心原则：

> 一个对话一个持久化缓存区；关键阶段生成版本；暂停保留 HEAD；继续从 HEAD 开始；只有对话彻底结束才发布正式状态。

## Git 类比

本方案借鉴 Git 的状态模型，但不使用 Git 存储 Agent 数据。

| Git | Agent Runtime |
|---|---|
| Working Tree | 当前 Turn 缓存区 |
| Index | 本轮待提交影响 |
| Commit | 不可变 Turn Version |
| HEAD | 当前有效恢复点 |
| Reflog | Turn 版本与状态变化记录 |
| Reset | 回到最后一个完整版本 |

世界观数据库、文档和文件不随 Turn 整体复制或回滚。Turn Version 只记录它们的 ID、revision 和操作收据。

## 运行模型

```text
正式状态
  ↓
Turn 缓存区
  ├── Version 0：本轮开始
  ├── Version 1：感知完成
  ├── Version 2：工具阶段完成
  ├── Version 3：子 Agent 阶段完成
  └── Final：整轮完成并正式提交
```

Turn 缓存区统一承载：

- 用户消息与发送时的页面快照。
- 当前执行阶段和恢复位置。
- Graph 工作状态。
- 已完成和待执行的工具记录。
- 子 Agent 运行引用及完成状态。
- 当前回复草稿。
- 待发布的消息、记忆、人格、任务和其他影响。
- 文档、文件及大型工具结果的引用。

不保存模型隐藏思维过程，只保存继续执行所需的事实、结果和阶段摘要。

## 暂停与继续

### 暂停

暂停不撤销、不提交，也不清空 Turn 缓存区。

1. 系统收到暂停请求。
2. 当前不可分割操作结束后进入稳定边界。
3. 保存新的 Turn Version。
4. 将 HEAD 指向该版本。
5. Turn 标记为暂停。

模型调用或工具调用进行到一半时，不将半成品标记为完成。协作式暂停默认等待当前调用结束。

### 继续

1. 读取当前 Turn 的 HEAD。
2. 恢复该版本中的工作状态、执行记录和待提交影响。
3. 从记录的下一阶段继续。
4. 不重复执行 HEAD 之前已经完成的动作。

同一进程内暂停可以继续使用内存缓存；持久化版本用于应用重启和异常恢复。

## 最终提交

只有 Agent 完整结束本轮后才能发布 Final：

1. 确认所有当前阶段已经闭合。
2. 生成最终回复和最终 Turn Version。
3. 一次性发布消息、记忆、人格、任务及其他正式影响。
4. 将 Turn 标记为完成。
5. 清理或归档不再需要的中间版本。

暂停版本和运行版本不能直接影响正式状态。

## 崩溃恢复

应用启动时检查未完成 Turn：

- 存在暂停版本：从 HEAD 继续。
- 运行中异常退出：回到最后一个完整版本。
- 没有完整版本：回到本轮开始前。
- 已存在 Final：不得重复执行或重复提交。

对于外部工具，恢复时依据调用标识和完成收据判断结果：

- 已完成：复用结果。
- 明确未执行：允许重新执行。
- 状态未知：先查询或进入待确认状态，不直接重放写操作。

## 版本保存时机

只在稳定边界生成版本：

- 本轮开始。
- 感知完成。
- 一次工具调用完成。
- 一个子 Agent 阶段完成。
- 收到暂停请求并到达稳定点。
- 最终提交前。

不按 Token 保存版本，也不要求每个轻量 Graph 节点都生成版本。流式回复草稿优先保留在内存，必要时按时间间隔持久化。

## 性能策略

Turn Version 使用“小状态快照 + 大数据引用”：

- 小型 Graph 状态、执行账本和待提交影响可以直接快照。
- 文档正文、图片、文件和大型工具结果只保存引用。
- 版本采用追加写，旧版本不反复更新。
- 一个 Turn 只维护一个 HEAD 指针。
- SQLite 使用单写入队列和事务，适合 Electron 单机运行。

普通对话预计产生约 3～8 个关键版本，数据库写入开销远小于模型推理和网络工具调用。主要风险不是版本数量，而是在每个版本中重复保存大型内容。

## 版本保留

- 未完成 Turn：保留全部关键版本。
- 已完成 Turn：默认保留 Final，调试模式可保留关键版本。
- 失败 Turn：保留最近若干版本用于恢复和检修。
- 超期完成版本可以自动清理。

## 首批验证场景

暂停、继续和恢复使用同一套协议，并按场景矩阵测试：

1. 普通对话。
2. 单个只读工具。
3. 多个连续工具。
4. 单个子 Agent。
5. 多个并行子 Agent。
6. 子 Agent 调用工具。
7. 工具完成后、最终提交前暂停。
8. 暂停后应用重启并继续。
9. 外部写操作状态未知时恢复。
10. 已有 Final 的 Turn 重启后不重复执行。

每个场景必须验证：

- HEAD 之前的完成结果不会丢失。
- 未完成动作不会被误报为完成。
- 继续后不会重复工具调用或重复创建子 Agent。
- 用户消息和页面快照不会串轮。
- 最终只提交一份回复和正式影响。
- 正常执行与暂停恢复执行得到一致的最终状态。

## 实施顺序

1. 建立最小 Turn Version、HEAD 和状态流转。
2. 接入普通对话和单个只读工具。
3. 建立暂停与恢复测试夹具。
4. 扩展到多工具。
5. 扩展到单个和多个子 Agent。
6. 最后处理外部写工具的查询、幂等和补偿语义。
