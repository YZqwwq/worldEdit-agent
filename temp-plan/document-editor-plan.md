# 文档编辑与版本待办

## 当前基线

- 文档工作区、ChangeSet、不可变内容版本、树快照和世界 Commit 已形成完整版本基座。
- 新增、更新、移动、排序和删除进入统一历史；人工编辑与 Agent 编辑保持各自提交边界。
- 用户停止输入约 3 秒后保存工作区，只有“创建版本”才产生正式人工 Commit。
- 已支持历史查看、版本比较、检查点、方案分支、三方合并、恢复、revert、cherry-pick、版本包和 GC。
- 局部编辑已支持精确替换、章节替换、锚点插入、末尾追加和章节读取。
- 局部修改会返回 revision、语义锚点和 `diffRef`；Diff 卡片可展开并定位编辑位置。
- Windows x64 与 macOS ARM64 的 Electron 原生测试矩阵已经建立。

## P0：统一编辑结果反馈

- `update_world_document` 修改完整正文时生成 `diffRef`，复用局部编辑的 Diff 卡片和语义定位；仅改标题时不生成正文 Diff。
- AI Diff 点击定位失败时在界面显示原因，不能只写控制台。
- 全文与局部编辑使用同一结果组装逻辑，避免 revision、增删统计和锚点字段继续分叉。

用户影响：无论 Agent 修改一段还是整篇，用户都能看到改了什么，并能直接跳到仍然有效的位置。

## P1：Agent 版本感知与控制

- 提供只读工具查看当前 HEAD、未封口 ChangeSet、最近版本和检查点。
- Agent 需要比较或解释历史时按需读取，不把提交图全量注入 Context。
- 是否开放 Agent 选择性恢复或 revert，等待只读能力和真实交互稳定后决定。

用户影响：Agent 能理解文档为什么变成现在这样，而不是只能读取当前正文。

## P1：编辑器结构化上下文

- 将当前选区、光标、选中文本和附近 TipTap 节点作为短期页面上下文。
- 只有现有 Markdown 语义锚点不足以稳定表达用户意图时，再增加节点级读取、替换、插入、删除和移动工具。
- 节点变化或定位失效必须返回结构化冲突，不猜测写入位置。

## P1：历史使用体验

- 根据真实历史量决定是否为最近 50 条列表增加分页与更强筛选。
- 继续保持工作区自动保存、正式版本和未来本地恢复三种职责分离。
- 编辑态是否长期统一为 Markdown，等待富文本节点和无损转换审计后决定。

## P2：由真实需求触发

- 未提交内容的独立本地历史，不伪装成正式 Commit。
- 多处编辑的单文档批量预检与原子应用。
- Codex 风格通用 Patch。
- Agent 撤销、章节 provenance、对象压缩、远端协商与密码学签名。

这些能力只有在现有语义工具、版本恢复或存储成本出现明确不足时再实现。
