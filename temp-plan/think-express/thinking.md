# 多维思考与认知交接

更新时间：2026-09-12。状态：当前能力分析与待实施方案。

## 目标

围绕具体事物完成用户要求，同时形成有意义的其他认识。保留自由思考，不把整个 cognition 改成逐项填表；结束时为 expression 留下足够交付的主线和可选择的方向。

## 已有能力

- cognitionPrompt.ts 已包含主线、延伸、证据与推测区分、人物印象查询要求。
- modelnode.ts 保留工具观察循环；当前 emulated 路径在进入 compose_final 时提取本次输出的 handoff。
- cognitionHandoff.ts 提取“主线结果：”“候选方向：”，只验证结构与长度，不验证事实。
- expression 优先消费 handoff。缺失时回退到明确标记的草稿；长草稿保留首尾，预算 4800 字符。

## 当前不足

| 问题 | 已知证据或代码限制 | 后果 |
| --- | --- | --- |
| 推断过度确定 | 历史测试将“不认为所有命令都错”推成认可具体命令 | 延伸污染事实主线 |
| 角度重复 | 多个品质标签围绕同一种人物解读 | 数量增加但信息不增加 |
| 交接漏细节 | 历史设计样本主线仅记录方案名称，缺参数 | expression 重新补写，可能偏离认识 |
| 交接只是文本协议 | 标题和 4800 字符检查不证明语义有效 | 提取成功不等于可用 |
| 工具可靠性有缺口 | 旧样本漏查印象、出现 TOOL_NOT_AVAILABLE | 未充分观察即形成结论 |
| 原生通道未覆盖同等交接 | handoff 写入位于 emulated 分支 | 不能声称所有模型都有相同候选输入 |
| 未表达的认识误记为已交流 | 生活状态由 expression 生成 | 后续可能跳过用户从未见过的内容 |

以上为静态检查及旧实验发现，2026-09-12 尚未重新实测。

## 交接内容

主线结果：用户要求、真实完成情况、足以交付的事实/方案、必要来源、仍未完成的部分。新方案应标明是建议而非既有事实，并保留具体参数。

候选方向：具体触发点、观点或疑问、依据、未知与其他可能解释、为什么值得本轮交流。没有合适候选允许为空。主观偏好可以存在，不要求将其伪装成客观结论。

长内容不能仅因预算而在交接中消失。实施前需确定正文承载方式：由 cognition 形成可交付素材并可控传递给 expression，或由 expression 根据已验证素材完成 artifact 正文。不能让 expression 在只有标题时虚构一整份报告。

## 优化顺序

1. 在已有隔离测试中补充证据反例和无延伸必要的场景，形成固定验收样本。
2. 分开统计主线准确性、候选不同性和候选依据，不用标题数量判通过。
3. 确认工具缺失属于激活、参数、执行还是模型未调用；按原因修复，不反复追加 prompt。
4. 检查交接完整性，尤其是长方案参数与来源。根据真实失败决定是否引入结构化交接数据，不为形式增加新节点。
5. 单独验证 native/emulated 两种路径，避免将原生隐藏推理当成可以完整导出的普通正文；显式模型内容应承担必要交接。

## 验收

- 请求要求阅读时有真实观察；额外编辑与长期保存不因发散自动发生。
- 候选非重复且有触发依据；没有值得延伸的内容时允许“无”。
- 事实摘要没有擅自增加时间、动机和行为细节。
- 面对纠正能修改错误解释，而非先认可再重复原结论。
- expression 获得本轮有效交接；缺失和截断可审计。
