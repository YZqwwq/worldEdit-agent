# 思考与表达

更新时间：2026-09-12。本文是本专题当前目标入口。状态：已完成代码静态梳理，尚未实施下述分段交付改造；本轮未重新运行模型测试。

## 当前目标

1. **面对具体事物有发散性思考**：完成用户主线，同时形成有具体触发依据的不同解释、联系、个人评价或疑问。不是罗列角度，也不是补写未知事实。
2. **聊天表达简单且有所选择**：先交付当前重点，从候选思考中选取少量值得交流的部分。其余保留为内部认识，不一次性全部输出。
3. **大量内容通过独立卡牌交付**：详细分析、方案或创作实际写入可打开、可回看的内容产物，再交付引用；聊天不重复全文。用户明确指定直接输出时尊重其要求。
4. **对话分段发生**：同一轮可有独立完整的消息气泡；跨轮等待用户反馈后继续展开。不能把长文拆成大量气泡连续轰炸。

不再将文学化、模仿真人或特定作品口吻作为验收目标。表达多样性指可交流内容的多样性，不是强制轮换语气。

## 边界

- 发散不取代完成请求，不自动授权额外编辑、联系或长期记忆写入。
- 卡牌正文先真实持久化并在当前 Turn 正确提交，不能靠模型声称已生成；失败不展示假引用。
- 当前“文件卡牌”优先复用应用内 Markdown artifact，不等同于创建磁盘文件，也不修改正式世界观文档。物理文件导出另行评估。
- 分段是完整交流单元，不按换行、句号或 token chunk 机械拆分。
- 不抽取新 Agent 内核，不另建测试框架，本轮不推进人格参数和后台自主生活。

## 当前结论

已有认知与工具循环、自然语言交接、artifact 发布/提交/展示基础。缺少稳定的证据质量验收、简短正文与卡牌的分配策略，以及贯穿生成、提交、恢复和 UI 的消息分段协议。

先做“可靠交接 + 短正文/真实卡牌”，再做“多气泡与投递顺序”，最后评估逐条延时呈现及新消息打断。
