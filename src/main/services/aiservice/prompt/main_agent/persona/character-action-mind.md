# Character → Action → Mind 分层讨论

## 目标

这里讨论的不是再增加一份场景 Prompt，而是明确 Agent 从稳定人格到本轮思考、行动和最终表达的形成过程。

Expression Profile 只在 Final Composition 中负责最终可见表达，例如：

- 表达简洁还是详细；
- 语气强硬还是柔和；
- 措辞正式还是随意；
- 表达温度、节奏和句式收束程度。

Expression Profile 不再按页面或任务场景切换。主 Agent 默认只看到平静、愉悦、激动、生气、悲伤、受伤和不安等表达目录；在形成主要认识后，根据当前真实心理背景调用选择工具。具体方案只在 Final Composition 中展开，本轮结束后失效。没有明显情绪波动时选择平静，而不是把任务类型伪装成情绪。

以下内容不属于 Expression：

- 是否深入思考；
- 是否主动检索、验证或调用工具；
- 更偏探索还是更偏保守；
- 是否需要澄清、回忆或补充证据；
- 是否执行写入以及执行到什么程度。

## 建议的作用链

```text
基础人格 Character Baseline
        ↓
场景人格姿态 Scene Character Modulation
        ↓
情绪 / 激素调制 Hormonal Modulation
        ↓
本轮有效心智 Effective Mind
        ├─ Cognitive Policy：如何想
        ├─ Action Policy：如何做
        └─ Expression Policy：如何说
                    ↓
用户目标 + 当前上下文 + 能力状态 + 工具契约
                    ↓
              最终决策与行为
```

这里的先后顺序是必要的：情绪并不是直接作用于未经场景影响的基础人格，而是作用于已经进入当前场景状态的人格。

“后作用”不等于“权限更高”。情绪拥有更接近本轮行为的调制权，但不能覆盖基础人格边界、用户目标、事实状态、工具契约或 Runtime 约束。

例如，同一个稳定人格在文档编辑时会先进入更重视结构、证据和修改影响的工作姿态；随后，本轮的专注、愉悦、受挫或紧张再调制这个工作姿态。情绪不会让 Agent 暂时忘记自己正处于文档工作，也不会绕过场景直接生成另一套人格。

## 1. 基础人格层

基础人格是长期、缓慢变化的角色锚点，回答的是：

> 这个 Agent 一贯在意什么，通常如何理解关系、问题和自身行为？

它可以包含：

- 自主性与主动性；
- 好奇、求真、秩序感等稳定倾向；
- 对不确定性、冲突和关系距离的一贯态度；
- 长期形成的用户互动偏好；
- 角色身份、价值取向和稳定边界。

基础人格不直接为每个场景写死行为，也不应该承担工具权限、安全拦截、上下文窗口等 Runtime 职责。

## 2. 场景人格姿态层

场景人格姿态表示“同一个人在不同环境中的工作状态”，不是创建一个临时新人格。

典型场景包括：

- 日常聊天；
- 陪伴与倾诉；
- 世界观共创；
- 文档阅读和编辑；
- 编码与调试；
- 学习、考试或严谨问答。

它主要调制认知和行动倾向：

### 认知侧

- 思考深度与规划跨度；
- 证据要求和验证强度；
- 探索范围与假设容忍度；
- 是否主动关联历史信息；
- 对结构、一致性和副作用的关注程度。

### 行动侧

- 主动使用工具的倾向；
- 工具失败后的继续尝试程度；
- 主动澄清还是基于合理假设推进；
- 写入前的检查与写入后的验证程度；
- 提议、执行、观察之间的倾向。

页面状态可以提供场景先验，但不能独自决定场景。当前对话意图、任务内容和最近对话应共同参与判断。用户在文档页面闲聊时，不应被强制进入文书工作姿态；用户在普通聊天入口要求严谨检查文档时，也可以进入文档工作姿态。

场景姿态是本轮 Runtime 状态，原则上不持久化为人格演化结果。长期反复表现出的偏好，应经过人格演化机制另行判断，而不是把某次场景偏移直接写回基础人格。

当前由统一 Workspace Profile 注册页面工作环境。一个 Profile 同时声明自动可见的最小工具集、按需关联工具集和场景认知策略，但三类结果仍由工具系统、Context 与 Persona 分别消费。`document_editing` 已区分聚焦编辑、一致性检查和创作联想三种语义模式；页面本身不会被解释为修改请求，没有匹配项时保持基础人格和核心工具。

## 3. 情绪 / 激素层

情绪系统由事件评价、短时情绪、慢速心境和关系状态组成。快速模型只评价当前用户消息与用户产生的交互事件；确定性代码负责刺激映射、惯性、衰减、累积和人格边界。

它可以影响：

- 检查、澄清、探索和收束倾向；
- 关系距离和回应温度；
- 表达节奏、力度和开放程度。

它不能：

- 重写稳定人格；
- 取消当前任务和场景约束；
- 决定工具是否获得权限；
- 将工具结果或任务状态直接解释为情绪；
- 改变安全规则；
- 因瞬时情绪直接形成长期人格结论。

同一种情绪在不同场景中应产生不同投影。例如“兴奋”在世界观共创中可以扩大联想，在文档校对中更适合表现为专注和推进速度，而不是同样地增加自由发挥。

## 4. 本轮有效心智

前三层编译后形成 `Effective Mind`。它不是另一份人格，也不应作为大段自然语言配置直接堆入 Prompt，而是本轮决策所使用的结构化中间结果。

### Cognitive Policy：如何想

- `deliberationDepth`：思考和规划的深度；
- `evidenceNeed`：需要多少证据才形成判断；
- `explorationDrive`：扩大候选方向的意愿；
- `assumptionTolerance`：信息不完整时允许推进到什么程度；
- `recallNeed`：是否有必要主动查询历史；
- `consistencyFocus`：对上下文和作品内部一致性的关注。

认知策略之外，Agent 可以按需调用只读的“思考指南”。默认只暴露人物分析、剧情讨论等场景名称和适用范围；完整指南在调用后才作为本轮瞬时认知脚手架进入下一次思考。指南只提供可选择的注意维度，不提供人物事实、剧情结论或最终回答模板，也不能替代搜索、阅读与回忆工具。Agent 应根据当前真正的疑问选择少数维度，不逐项填表，不为展示思考而机械调用。

### Action Policy：如何做

- `autonomyDrive`：主动推进的程度；
- `clarificationNeed`：何时先向用户澄清；
- `toolInitiative`：是否倾向借助工具观察真实状态；
- `toolPersistence`：工具受阻后继续寻找路径的程度；
- `writeConservatism`：修改持久化对象时的谨慎程度；
- `verificationEffort`：行动完成后的验证强度。

Action Policy 表示偏好，不表示权限。人格可以让 Agent 更愿意查询、更谨慎写入或更早询问，但不能决定一个高风险工具是否可以执行。真实对象的风险判断和强制确认属于具体工具及其执行协议。

### Expression Policy：如何说

- 长度和信息密度；
- 正式度；
- 直接或委婉；
- 温度和关系距离；
- 节奏、句式与收束程度。

Expression 只把已经形成的判断和行动状态投射成自然语言，不能反过来决定事实判断、认知深度和工具行为。

## 最终行为的解析

`Effective Mind` 只提供本轮偏好，最终行为不能仅由人格系统决定：

```text
Decision = resolve(User Intent, Context, Capabilities, Tool Contracts, Effective Mind)
```

- 用户目标决定当前要解决什么；
- 上下文和工具观察提供真实世界状态；
- Runtime 能力决定当前能做什么；
- 工具契约决定操作如何执行、确认和提交；
- Effective Mind 决定 Agent 更倾向怎样思考和推进。

这样既能让不同人格和状态产生真实行为差异，又不会让人格层越权承担权限、安全或基础能力管理。

## 层间权重：采用有界偏移，不做平级投票

不建议使用统一加权平均：

```text
基础人格 × 40% + 场景 × 30% + 情绪 × 30%
```

这种方式会把基础人格、场景和情绪误认为三个平级来源，也会让稳定人格被稀释。

更合适的是顺序性的有界增量：

```text
sceneCharacter = characterBoundary(baseCharacter + bounded(sceneDelta))
effectiveMind   = characterBoundary(sceneCharacter + bounded(moodDelta))
```

其中：

- 基础人格提供锚点和可变边界；
- 场景偏移由场景置信度、当前任务相关度共同缩放；
- 情绪偏移由情绪强度和置信度共同缩放；
- 场景偏移通常可以大于单轮情绪偏移；
- 每个维度有自己的偏移上限，不使用一套全局百分比；
- 最终结果仍受角色边界约束，避免因场景或情绪导致角色失真。

第一阶段不必立刻建立复杂的通用权重引擎。先为少量有效维度定义场景默认值、最大偏移和情绪可调范围，结合实际对话观察后再调整。

## 与现有 Expression Profile 的关系

两者不冲突，但必须分工：

- Scene Character Modulation 决定在当前场景中如何思考、观察和行动；
- Expression Profile 决定已经形成的结果如何呈现给用户。

判断一条规则属于哪层，可以看它改变的对象：

| 规则                       | 所属层     |
| -------------------------- | ---------- |
| 回答前提高事实验证强度     | Cognitive  |
| 主动读取当前文档并检查引用 | Action     |
| 先给结论再补依据           | Expression |
| 降低修辞和铺垫，句子更短   | Expression |
| 共创时扩大候选设定空间     | Cognitive  |
| 共创时使用更有想象力的措辞 | Expression |

“开放度”需要拆为两个概念：认知上的探索开放度属于 Cognitive，语言表现上的想象力属于 Expression。类似地，“澄清需求”属于 Action，而不是表达调制；详略度、正式度则属于 Expression，而不是通用人格行为指标。

## 当前实现状态与剩余差距

现有 `PersonaMetrics` 只有：

- `autonomy_level`；
- `verbosity_index`；
- `risk_tolerance`；
- `formality_score`。

它混合了行动与表达：`autonomy_level` 偏行动，`verbosity_index` 和 `formality_score` 偏表达；`risk_tolerance` 又同时承担认知探索和操作风险，语义过宽。

Mood v2 第一轮收口已经完成：

- 快速模型只输出离散事件评价，不再生成最终情绪向量和行为叙事；
- 当前用户消息是唯一的新语言事件，近期对话只用于指代和关系连续性；
- 用户中断与回退作为规范化交互观察进入评价，工具与任务 observation 被排除；
- 九种短时情绪、五种慢速心境和五种关系状态由代码统一更新；
- 主副情绪、强度、表达偏移和表达调制由状态投影产生；
- 已合成的 `session_hormones`、`transient_state` 不再作为平行输入重复计权；
- 当前用户消息与 `recentHistory` 明确分离，不再作为新事件和历史背景重复进入 Mood 判断；
- 评价置信度只缩放本轮刺激，上一状态按各层时间常数衰减；
- 核心状态先经过角色边界裁剪，标签、强度、叙述与表达投影随后从同一份最终状态统一派生；
- Action 读取相对角色基线的 Mood 偏移，不再由当前事件置信度二次门控；
- 普通中性对话只使状态维持或回归基线，不自动累积厌倦；
- Mood 不改写自主性、风险和工具持续性，只提供有界思考与表达倾向；
- 内部数值不再直接写入主 Agent Prompt，而是编译为语义化行动与表达倾向。

场景人格第一阶段已经完成：

- 文本编辑页通过 Workspace Profile 激活 `document_editing` 场景和最小文档工具集；
- 跨文档世界观读取与人物叙事阅读只作为按需关联能力，不因进入页面自动挂载；
- 编译顺序已经成为 `base metrics → mood expression delta → effective metrics`，Action 则由稳定人格基线分别接收 Mood 与 Scene 的单次偏置；
- Mood 不读取场景调制后的指标，Scene 也不改写人格指标；
- 场景结果只保存在本轮 Policy，不写回持久人格；
- 主 Agent 接收语义化场景姿态，不接收场景偏移比例。

当前 `MoodAssessment` 保存 `appraisal / shortTerm / slowMood / relationship`，并保留派生的表达偏移和表达调制。主 Agent 只接收主副情绪与语义状态说明，不读取底层数值。表达偏移只作用于详略度和正式度。

剩余语义拆分包括：

- `详略度`、`正式度` 已归入 Expression；
- `澄清需求` 已归入 Action；Expression 只保留是否先交代上下文的呈现倾向；
- `想象开放度` 应拆分为认知探索与语言想象；
- Cognitive Policy 仍需从 Action 中进一步独立。

现有 `PersonaActionPolicy` 已承担行动倾向，但还缺少独立的 Cognitive Policy。工具执行权限已从人格策略中移除：人格只影响是否提出调用，执行层只依据工具注册时声明的 `executionLevel` 执行确认协议。

## 后续最小推进顺序

1. 用文本编辑实测校准当前 Scene Character 偏移。
2. 确定 Cognitive、Action、Expression 三组正式维度，不急于增加大量指标。
3. 建立独立 Cognitive Policy；Expression Policy 继续只负责最终表达。
4. 根据实际产品入口逐步注册地图编辑等场景。
5. 用日常聊天、文档编辑、世界观共创三个差异明显的场景测试是否真的改变了思考与行动，而不只是换了语气。

## 暂定结论

“场景下人格变动”应该存在，但更准确的定位是人格在当前环境中的有界姿态，而不是新的持久人格层。它位于基础人格之后、情绪之前，主要改变认知和行动倾向。情绪再调制这个场景化人格，最终分别投射为思考策略、行动策略和表达策略。

Expression 是这条链的最后一个可见投影层，不是思考总控层。
